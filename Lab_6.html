Lab 8: PHP forms and server-side validation

Instructions

In this lab you will receive form data in PHP, validate every field on the server, and redisplay the form with the user's values and an error message next to each wrong field.
You will then apply the Post/Redirect/Get pattern, handle file uploads securely, and insert the validated data in the database with PDO (Lab 6).
Useful lectures: Introduction to PHP (strings, arrays, functions) and Security (SQL injection, XSS, filesystem security). At the end of the lab, every form of your project must be validated on the server.

I. Why validate on the server?

In Lab 4 you validated your forms with JavaScript. That validation is good for the user experience: errors appear immediately, without reloading the page. But it gives no security at all, because it runs on the visitor's machine, which you do not control:

  • JavaScript can be disabled in the browser.
  • The required, maxlength and pattern attributes can be removed in two seconds with the browser developer tools (F12).
  • Anyone can send a request directly to your PHP file, without using your form at all, with tools such as curl or Postman.

So the rule is: JavaScript validation is optional comfort, server-side validation is mandatory. Keep both, with the same rules. And remember the two halves of input/output security: validate the input (this lab), escape the output with htmlspecialchars() and use prepared statements for the database (Lab 6).

curl -X POST http://localhost/your_project/register.php \

II. Receiving form data

$_GET or $_POST?

  • method="get": the data is added to the URL (search.php?q=mouse&page=2) and read in $_GET. The URL can be bookmarked and shared. Use it for requests that only read data: search, filters, pagination.
  • method="post": the data is sent in the body of the request and read in $_POST. Use it for everything that changes data (create, update, delete, login) and for sensitive values such as passwords, which must never appear in a URL, the browser history or the server logs. File uploads also require POST.
  • $_SERVER['REQUEST_METHOD'] tells you how the page was requested: 'GET' when the user simply opens it, 'POST' when the form is submitted. This lets one PHP file both display the form and process it.
<!-- search.php: a GET form -->
<form method="get" action="search.php">
  <input type="search" name="q" placeholder="Search a product">
  <button type="submit">Search</button>
</form>
        
<?php
// search.php?q=mouse&page=2
declare(strict_types=1);

// A field can be missing, or even sent as an array (q[]=x): never assume it is a string.
$q = isset($_GET['q']) && is_string($_GET['q']) ? trim($_GET['q']) : '';

// Missing or invalid page number: fall back to page 1.
$page = filter_input(INPUT_GET, 'page', FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]) ?: 1;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // the form was submitted with method="post"
}

isset(), empty() and trim()

  • isset($_POST['email']) is true if the field was sent and is not null. It does not say anything about the content: an empty field is still "set".
  • empty($x) is true for '', '0', 0, null, false and []. Be careful: a user who types 0 (a quantity, a mark...) would be considered as "empty".
  • trim() removes spaces, tabs and line breaks at both ends. Without it, a field containing only spaces passes the "required" check.
  • The null coalescing operator ?? gives a default value when the key does not exist: $_POST['city'] ?? ''.
<?php
/** Returns a POST field as a string ('' if missing or not a string), trimmed by default. */
function post_string(string $key, bool $trim = true): string
{
    $value = $_POST[$key] ?? '';
    if (!is_string($value)) {
        return '';
    }
    return $trim ? trim($value) : $value;
}

$name = post_string('full_name');
if ($name === '') {              // more precise than empty(): '0' is a real value
    echo 'The name is required.';
}

III. Validation rules

filter_input() and filter_var()

PHP's filter extension validates common formats. filter_var($value, FILTER) checks a value you already have; filter_input(INPUT_POST, 'name', FILTER) reads the field directly from the request. Both return the valid value (converted to the right type) or false if it is invalid; filter_input() returns null if the field is missing. Always compare with ===. 

<?php
// Email: returns the string, or false
$email = filter_input(INPUT_POST, 'email', FILTER_VALIDATE_EMAIL);
if ($email === null || $email === false) {
    $errors['email'] = 'Please enter a valid email address.';
}

// Integer in a range: returns an int, or false ('12abc', '3.5', '-1', '200' are rejected)
$age = filter_input(INPUT_POST, 'age', FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 16, 'max_range' => 120],
]);
if ($age === null || $age === false) {
    $errors['age'] = 'Age must be a whole number between 16 and 120.';
}

// Same thing with a value you already have
$quantity = filter_var('3', FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);   // int(3)
$price    = filter_var('12.50', FILTER_VALIDATE_FLOAT);                               // float(12.5)
$website  = filter_var('https://ensia.edu.dz', FILTER_VALIDATE_URL);                  // the string
$agree    = filter_var('yes', FILTER_VALIDATE_BOOLEAN);                               // true ("1", "on", "yes", "true")
Avoid FILTER_SANITIZE_STRING: it is deprecated since PHP 8.1. Do not "clean" input by deleting characters: validate it (accept or reject) and escape it when you print it. Also note that FILTER_VALIDATE_EMAIL only checks the format, not that the mailbox exists.

Required fields, lengths and regular expressions

For rules that filters do not cover, use string functions and preg_match(), which returns 1 if the regular expression matches, 0 otherwise. Use mb_strlen() instead of strlen() to count characters: strlen() counts bytes, and an Arabic or accented letter takes 2 bytes in UTF-8. For a <select> or radio buttons, check that the value belongs to the list of allowed values (a whitelist), because the user can send any value. 

<?php
// Required + length
if ($name === '') {
    $errors['full_name'] = 'Full name is required.';
} elseif (mb_strlen($name) < 3 || mb_strlen($name) > 100) {
    $errors['full_name'] = 'Full name must contain between 3 and 100 characters.';
} elseif (!preg_match('/^\p{L}[\p{L} \'-]*$/u', $name)) {
    // \p{L} = any letter (Latin, Arabic...), the "u" flag enables UTF-8
    $errors['full_name'] = 'Only letters, spaces, hyphens and apostrophes are allowed.';
}

// Algerian mobile number: 10 digits starting with 05, 06 or 07 (e.g. 0551234567)
if (!preg_match('/^0[567][0-9]{8}$/', $phone)) {
    $errors['phone'] = 'Enter a mobile number such as 0551234567.';
}

// Password: at least 8 characters, one letter and one digit
if (strlen($password) < 8 || !preg_match('/[A-Za-z]/', $password) || !preg_match('/[0-9]/', $password)) {
    $errors['password'] = 'At least 8 characters, including a letter and a digit.';
}

// Whitelist for a <select>
const ACCOUNT_TYPES = ['customer' => 'Customer', 'seller' => 'Seller'];
if (!array_key_exists($accountType, ACCOUNT_TYPES)) {
    $errors['account_type'] = 'Please choose an account type.';
}

IV. Errors array and sticky form

A good form never shows a blank page saying "error". Instead, it:

  1. validates all the fields and stores each problem in an array $errors['field_name'], so the user sees every error at once;
  2. redisplays the form with the values the user typed (a sticky form), except passwords;
  3. shows each message next to its field;
  4. escapes every value it prints with htmlspecialchars(), including the values put back into value="..." attributes.

We build a complete register.php for this users table. Create it in your shop_lab database from Lab 6: 

CREATE TABLE users (
  id             INT UNSIGNED     NOT NULL AUTO_INCREMENT,
  full_name      VARCHAR(100)     NOT NULL,
  email          VARCHAR(255)     NOT NULL,
  age            TINYINT UNSIGNED NOT NULL,
  phone          CHAR(10)         NOT NULL,
  account_type   VARCHAR(20)      NOT NULL,
  password_hash  VARCHAR(255)     NOT NULL,
  avatar         VARCHAR(100)     NULL,
  created_at     TIMESTAMP        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_users_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

<?php

function e(string $value): string
{
    return htmlspecialchars($value, ENT_QUOTES, 'UTF-8');
}

function post_string(string $key, bool $trim = true): string
{
    $value = $_POST[$key] ?? '';
    if (!is_string($value)) {
        return '';
    }
    return $trim ? trim($value) : $value;
}

/** HTML for the error message of one field ('' if there is none). */
function field_error(array $errors, string $field): string
{
    if (!isset($errors[$field])) {
        return '';
    }
    return '<span class="error">' . e($errors[$field]) . '</span>';
}

$errors = [];
$old = [                      // values redisplayed in the form
    'full_name'    => '',
    'email'        => '',
    'age'          => '',
    'phone'        => '',

Why escape the sticky values? If a user types "><script>alert(1)</script> in the name field and you print value="<?= $old['full_name'] ?>" without escaping, the quote closes the attribute and the script runs in the page: this is reflected XSS. With e() the quote becomes &quot; and the text is displayed harmlessly.

V. Saving with PDO and the Post/Redirect/Get pattern

When the data is valid, we insert it with a prepared statement (Lab 6). Then we must not display the result page directly: if the user refreshes it, the browser re-sends the POST request ("Confirm form resubmission") and the account would be created twice. The Post/Redirect/Get (PRG) pattern avoids this:

  1. the browser POSTs the form;
  2. on success, the server answers with a redirect (header('Location: ...'), status 303 "See Other") and stops the script with exit;
  3. the browser follows it with a GET request. Refreshing now only repeats the harmless GET.

On failure (validation errors), there is no redirect: the same request displays the form with the errors and the sticky values. Passwords are stored with password_hash(), never in clear text.

Part 3: insertion and redirect

    // Inside "if ($_SERVER['REQUEST_METHOD'] === 'POST') { ... }", after the validation:
    if (count($errors) === 0) {
        try {
            $stmt = getConnection()->prepare(
                'INSERT INTO users (full_name, email, age, phone, account_type, password_hash)
                 VALUES (:full_name, :email, :age, :phone, :account_type, :password_hash)'
            );
            $stmt->execute([
                ':full_name'     => $old['full_name'],
                ':email'         => $old['email'],
                ':age'           => $age,                 // the int returned by filter_var()
                ':phone'         => $old['phone'],
                ':account_type'  => $old['account_type'],
                ':password_hash' => password_hash($password, PASSWORD_DEFAULT),
            ]);

            // Post/Redirect/Get
            header('Location: register.php?registered=1', true, 303);
            exit;
        } catch (PDOException $e) {
            if (($e->errorInfo[1] ?? null) === 1062) {    // duplicate key: the UNIQUE email
                $errors['email'] = 'An account with this email already exists.';
            } else {
                error_log($e->getMessage());
                $errors['form'] = 'Something went wrong. Please try again later.';
            }
        }
    }
Important: header() only works if nothing has been sent to the browser yet, not even a space or an empty line before <?php. That is why all the processing is at the top of the file and the HTML at the bottom. Always write exit; after a redirect, otherwise the rest of the script keeps running. VI. Secure file upload

An upload form must use method="post" and enctype="multipart/form-data". PHP stores the file in a temporary folder and describes it in $_FILES['field_name']:

  • name: the original file name, chosen by the user. Never trust it and never use it to save the file.
  • type: the MIME type sent by the browser. Never trust it either; it is just text the client can change.
  • tmp_name: where PHP stored the file on the server.
  • size: the size in bytes.
  • error: UPLOAD_ERR_OK (0) on success, otherwise UPLOAD_ERR_INI_SIZE (bigger than upload_max_filesize in php.ini), UPLOAD_ERR_FORM_SIZE (bigger than the form's MAX_FILE_SIZE), UPLOAD_ERR_PARTIAL, UPLOAD_ERR_NO_FILE (no file chosen), UPLOAD_ERR_NO_TMP_DIR, UPLOAD_ERR_CANT_WRITE or UPLOAD_ERR_EXTENSION (server problems).

A secure upload follows these steps: check the error code, check the size, detect the real type from the file content with finfo (if PHP says Class "finfo" not found, enable extension=fileinfo in php.ini and restart Apache), accept only a whitelist of types, generate a random file name with an extension chosen by you, then move the file with move_uploaded_file(). The lecture Storing data with PHP shows the basic upload; here is the secure version.

<form method="post" action="upload_avatar.php" enctype="multipart/form-data">
  <!-- MAX_FILE_SIZE must come before the file input; it is only a hint, PHP checks the size again -->
  <input type="hidden" name="MAX_FILE_SIZE" value="2097152">
  <label for="avatar">Profile picture (JPEG, PNG or WebP, 2 MB max)</label>
  <input type="file" id="avatar" name="avatar" accept="image/jpeg,image/png,image/webp">
  <button type="submit">Upload</button>
</form>
        
<?php
// includes/upload.php
declare(strict_types=1);

const MAX_UPLOAD_SIZE = 2 * 1024 * 1024;            // 2 MB
const ALLOWED_IMAGE_TYPES = [                        // real MIME type => extension we choose
    'image/jpeg' => 'jpg',
    'image/png'  => 'png',
    'image/webp' => 'webp',
];
const UPLOAD_DIR = __DIR__ . '/../uploads/avatars/';

/**
 * Validates an uploaded image and moves it to UPLOAD_DIR.
 * Returns the new file name, or throws a RuntimeException with a message for the user.
 */
function storeUploadedImage(array $file): string
{
    if (!isset($file['error']) || is_array($file['error'])) {
        throw new RuntimeException('Invalid upload.');   // missing field or several files sent
    }

    $message = match ($file['error']) {
        UPLOAD_ERR_OK                             => null,
        UPLOAD_ERR_NO_FILE                        => 'Please choose a file.',
        UPLOAD_ERR_INI_SIZE, UPLOAD_ERR_FORM_SIZE => 'The file is too large (2 MB max).',
        UPLOAD_ERR_PARTIAL                        => 'The upload was interrupted. Please try again.',
        default                                   => 'The server could not receive the file.',
    };
    if ($message !== null) {
        throw new RuntimeException($message);
    }

    if ($file['size'] > MAX_UPLOAD_SIZE) {
        throw new RuntimeException('The file is too large (2 MB max).');
    }

    // Real type, detected from the content of the file (not from its name or from the browser)
    $finfo = new finfo(FILEINFO_MIME_TYPE);
    $mime = $finfo->file($file['tmp_name']);
    if ($mime === false || !array_key_exists($mime, ALLOWED_IMAGE_TYPES)) {
        throw new RuntimeException('Only JPEG, PNG and WebP images are allowed.');
    }

    // Random name: no overwriting, no guessing, no "../" or ".php" coming from the user
    $newName = bin2hex(random_bytes(16)) . '.' . ALLOWED_IMAGE_TYPES[$mime];

    if (!is_dir(UPLOAD_DIR) && !mkdir(UPLOAD_DIR, 0755, true)) {
        throw new RuntimeException('The server could not save the file.');
    }
    // move_uploaded_file() also checks that tmp_name really is a file uploaded by this request
    if (!move_uploaded_file($file['tmp_name'], UPLOAD_DIR . $newName)) {
        throw new RuntimeException('The server could not save the file.');
    }

    return $newName;
}
        
<?php
// upload_avatar.php (processing part)
declare(strict_types=1);

require_once __DIR__ . '/includes/upload.php';

$errors = [];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    try {
        $avatar = storeUploadedImage($_FILES['avatar'] ?? []);
        // Save $avatar (the file name only, not the full path) in the database with PDO,
        // e.g. UPDATE users SET avatar = :avatar WHERE id = :id, then redirect (PRG).
        header('Location: upload_avatar.php?uploaded=1', true, 303);
        exit;
    } catch (RuntimeException $e) {
        $errors['avatar'] = $e->getMessage();   // displayed next to the field with field_error()
    }
}

Finally, make sure a file placed in the upload folder can never be executed as PHP. The best solution is a folder outside htdocs, served through a PHP script. If the folder must stay inside your project, add this .htaccess file in it (Apache, as in XAMPP):

# uploads/.htaccess : refuse to serve or run scripts from this folder
<FilesMatch "\.(php|phtml|phar|php[0-9])$">
    Require all denied
</FilesMatch>
Options -ExecCGI -Indexes
Watch out: if the whole request is bigger than post_max_size (php.ini), PHP silently empties both $_POST and $_FILES. Your code then sees a POST request with no fields: treat it as an error, do not crash. See also the "Filesystem Security" part of the Security lecture.
