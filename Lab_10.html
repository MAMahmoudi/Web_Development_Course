III. Check a fresh installation

"It works on my computer" is not enough: a missing extension, a forgotten table or a folder that cannot be written only appear on another computer. Syaha checks them with a small script, run in a terminal:

tools/check_install.php

<?php
// Checks that this computer (or server) can run Syaha (Lab 10).
// Run it in a terminal, from the folder of the project:   php tools/check_install.php
// It is not a page of the website: tools/.htaccess refuses it to the browsers.
if (PHP_SAPI !== 'cli') {
    http_response_code(404);
    exit;
}

$root = dirname(__DIR__);
$failures = 0;

function report(string $status, string $message): void
{
    global $failures;
    if ($status === 'FAIL') {
        $failures++;
    }
    echo str_pad("[$status]", 7) . $message . PHP_EOL;
}

// ------------------------------------------------------------------ PHP
version_compare(PHP_VERSION, '8.1.0', '>=')
    ? report('OK', 'PHP ' . PHP_VERSION)
    : report('FAIL', 'PHP ' . PHP_VERSION . ': Syaha needs PHP 8.1 or newer');

foreach (['pdo_mysql' => 'the database', 'mbstring' => 'Arabic texts', 'fileinfo' => 'the uploads'] as $extension => $use) {
    extension_loaded($extension)
        ? report('OK', "extension $extension")
        : report('FAIL', "extension $extension is missing ($use): enable it in php.ini");
}

// ------------------------------------------------------------------ settings
require $root . '/includes/config.php';

is_file($root . '/includes/config.local.php')
    ? report('OK', 'includes/config.local.php found')
    : report('WARN', 'no includes/config.local.php: the XAMPP defaults are used (root, no password)');
APP_DEBUG
    ? report('WARN', 'APP_DEBUG is true: never on a public server')
    : report('OK', 'APP_DEBUG is false: errors are logged, not shown');
DB_USER === 'root'
    ? report('WARN', 'the database account is root: create an account for the site on a server')
    : report('OK', 'database account: ' . DB_USER);

// ------------------------------------------------------------------ database
try {
    $pdo = new PDO('mysql:host=' . DB_HOST . ';port=' . DB_PORT . ';dbname=' . DB_NAME . ';charset=utf8mb4',
        DB_USER, DB_PASS, [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]);
    report('OK', 'connected to the database ' . DB_NAME . ' on ' . DB_HOST . ':' . DB_PORT);

    // the tables expected: the ones created by database/syaha.sql
    preg_match_all('/CREATE TABLE (\w+)/', file_get_contents($root . '/database/syaha.sql'), $matches);
    $existing = $pdo->query('SHOW TABLES')->fetchAll(PDO::FETCH_COLUMN);
    $missing = array_diff($matches[1], $existing);
    $missing
        ? report('FAIL', 'missing tables: ' . implode(', ', $missing) . ' (import database/syaha.sql)')
        : report('OK', count($matches[1]) . ' tables');

    if (!$missing) {
        // the demo password of the admin must be changed before the site is public
        $hash = $pdo->query("SELECT password_hash FROM users WHERE email = 'admin@syaha.example'")->fetchColumn();
        $hash && password_verify('Syaha_Admin1', $hash)
            ? report('WARN', 'the admin account still has its demo password')
            : report('OK', 'no demo password for the admin account');
    }
} catch (PDOException $e) {
    report('FAIL', 'database: ' . $e->getMessage());
}

// ------------------------------------------------------------------ files
is_writable($root . '/uploads/trips')
    ? report('OK', 'uploads/trips is writable')
    : report('FAIL', 'uploads/trips is not writable: the photos of the trips cannot be uploaded');
foreach (['uploads/trips/.htaccess', 'includes/.htaccess', 'database/.htaccess', 'tools/.htaccess'] as $file) {
    is_file($root . '/' . $file)
        ? report('OK', "$file protects its folder")
        : report('FAIL', "$file is missing");
}

echo PHP_EOL . ($failures ? "$failures problem(s) to fix." : 'Ready.') . PHP_EOL;
exit($failures ? 1 : 0);

IV. Writing a good README.md

The README.md file is displayed on the home page of your GitHub repository. It is the first thing a teacher, a classmate or a future employer reads: what the project does, and above all how to install it. The README of Syaha is a model; write yours with the same sections:

README.md

# Syaha (سياحة) – a travel agency website

Syaha is the demo project of the *Web Development* course (ENSIA): the website of an Algerian travel agency, in
Arabic (right to left). Visitors discover the trips, book them and send messages; customers have an account with
their bookings; the agency manages trips, bookings and messages in an admin area.

It was built step by step in the labs of the course: HTML and CSS (Lab 2), responsive design (Lab 3), JavaScript
(Lab 4), MySQL and PDO (Lab 5), server-side validation and uploads (Lab 6), sessions and accounts (Lab 7) and
security (Lab 9). This folder is the final version (Lab 10).

| For | Feature |
| --- | --- |

| Customers | registration, login and logout, "remember my e-mail", their bookings, cancellation of a pending booking, forms pre-filled with their name |
| Admins | dashboard, trips (create, edit with photo upload, publish, delete), bookings (confirm, cancel), messages (read, delete) |
| Security | prepared statements, escaped output, CSRF tokens, hashed passwords, login throttling, session hardening, Content-Security-Policy and security headers, safe uploads, secrets out of Git |

## Technologies

HTML5, CSS3 (Flexbox, Grid, media queries), JavaScript (no framework), PHP 8.1+ (PDO), MySQL / MariaDB, Apache

V. Exporting the database

Your PHP code is useless without the database. Syaha keeps it in one file, database/syaha.sql, that re-creates everything:

database/syaha.sql (extract)

-- Syaha: database of the demo website (Lab 5, users added in Lab 7, login_attempts in Lab 9)
-- Import it in phpMyAdmin (Import tab) or with:
--   mysql -u root < database/syaha.sql
-- Importing again deletes the tables and their data and recreates them.
-- ------------------------------------------------------------------

CREATE DATABASE IF NOT EXISTS syaha CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE syaha;

-- children first: a table cannot be dropped while another table references it
DROP TABLE IF EXISTS bookings;
DROP TABLE IF EXISTS contact_messages;
DROP TABLE IF EXISTS trips;
DROP TABLE IF EXISTS destinations;
DROP TABLE IF EXISTS services;
DROP TABLE IF EXISTS team_members;
DROP TABLE IF EXISTS login_attempts;
DROP TABLE IF EXISTS users;
  • The tables are dropped in the reverse order of their foreign keys (a booking refers to a trip and a user: bookings is dropped first), then created in the right order.
  • utf8mb4 everywhere: Arabic texts and emojis are stored correctly.
  • A small but realistic data set: a few trips, bookings, messages and two demo accounts, so that the demo looks alive. No real personal data, no real password.

If your database was built in phpMyAdmin, export it: select the database, tab Export, method Custom, format SQL, check Add DROP TABLE, then save it in the database/ folder of the repository. From the command line: 

# export: structure + data, in the database/ folder of the project (Git Bash)
/c/xampp/mysql/bin/mysqldump -u root --databases syaha --default-character-set=utf8mb4 > database/syaha_dump.sql

# import on another computer
/c/xampp/mysql/bin/mysql -u root --default-character-set=utf8mb4 < database/syaha.sql

# the hash of a demo password, to write in the SQL file
/c/xampp/php/php -r "echo password_hash('Syaha_2025', PASSWORD_DEFAULT), PHP_EOL;"
Test it: drop your local database (or use a teammate's computer), import the file, and run check_install.php. If the import fails for you, it fails for the reviewers.

VI. Git workflow hygiene

The repository is part of the evaluation: it shows how the team worked. A clean history has one branch per feature, changes merged through pull requests reviewed by another member, small commits with meaningful messages, and contributions from every member.

VII. End-to-end testing

End-to-end testing means using the application like a real user, from the browser to the database and back. Syaha has an automatic smoke test: a quick check that nothing is broken, to run after every merge and before the presentation.

tools/smoke_test.php

<?php
// End-to-end "smoke test" of Syaha (Lab 10): requests the pages like a browser and checks the answers.
// Run it in a terminal while Apache and MySQL are started, with the address of the site:
//   php tools/smoke_test.php http://localhost/<project folder>/SRC/Labs/Lab_10/
// It only reads pages and sends forms WITHOUT their token: it changes nothing in the database.
if (PHP_SAPI !== 'cli') {
    http_response_code(404);
    exit;
}
if ($argc < 2) {
    exit('Usage: php tools/smoke_test.php http://localhost/<project folder>/SRC/Labs/Lab_10/' . PHP_EOL);
}

$base = rtrim($argv[1], '/') . '/';
$passed = $failed = 0;

/** One HTTP request (no redirect followed): returns [status, headers, body]. */
function request(string $url, ?array $post = null): array
{
    $curl = curl_init($url);
    curl_setopt_array($curl, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HEADER => true,
        CURLOPT_FOLLOWLOCATION => false,
        CURLOPT_TIMEOUT => 10,
    ]);
    if ($post !== null) {
        curl_setopt($curl, CURLOPT_POSTFIELDS, http_build_query($post));
    }
    $response = curl_exec($curl);
    if ($response === false) {
        exit('Cannot reach ' . $url . ': ' . curl_error($curl) . PHP_EOL);
    }
    $size = curl_getinfo($curl, CURLINFO_HEADER_SIZE);
    $status = curl_getinfo($curl, CURLINFO_RESPONSE_CODE);
    curl_close($curl);
    return [$status, strtolower(substr($response, 0, $size)), substr($response, $size)];
}

function check(string $name, bool $ok): void
{
    global $passed, $failed;
    $ok ? $passed++ : $failed++;
    echo ($ok ? '[OK]   ' : '[FAIL] ') . $name . PHP_EOL;
}

// public pages
foreach (['index.php', 'services.php', 'about_us.php', 'contact_us.php', 'login.php', 'register.php', 'book.php?trip=1'] as $page) {
    [$status, , $body] = request($base . $page);
    check("$page answers 200", $status === 200 && str_contains($body, '</html>'));
}
[$status] = request($base . 'services.php?max_price=20000&sort=price_asc');
check('search with GET', $status === 200);
[$status] = request($base . '404.php');
check('404.php answers 404', $status === 404);

// security headers
[, $headers] = request($base . 'index.php');
foreach (['content-security-policy', 'x-content-type-options', 'x-frame-options', 'referrer-policy'] as $header) {
    check("header $header", str_contains($headers, $header . ':'));
}
check('session cookie HttpOnly and SameSite', str_contains($headers, 'httponly') && str_contains($headers, 'samesite=lax'));
check('no X-Powered-By', !str_contains($headers, 'x-powered-by:'));

// protected pages
foreach (['my_bookings.php', 'admin/index.php', 'admin/trips.php', 'admin/bookings.php', 'admin/messages.php'] as $page) {
    [$status, $headers] = request($base . $page);
    check("$page redirects a visitor to the login", $status === 302 && str_contains($headers, 'location: ') && str_contains($headers, 'login.php?next='));
}

// forms posted without their CSRF token: refused (303 to the same page), nothing changed
foreach (['contact_us.php', 'book.php', 'login.php', 'admin/trip_delete.php'] as $page) {
    [$status] = request($base . $page, ['name' => 'smoke test', 'email' => 'test@example.com', 'id' => '1']);
    check("POST $page without token is refused", $status === 303);
}

// files that must never be served (Apache with .htaccess)
foreach (['includes/config.php', 'database/syaha.sql', 'tools/check_install.php'] as $file) {
    [$status] = request($base . $file);
    check("$file is not served", $status === 403 || $status === 404);
}

echo PHP_EOL . "$passed passed, $failed failed." . PHP_EOL;
exit($failed ? 1 : 0);

Browser DevTools

Open the DevTools (F12) on every page while you test. The Console tab must show no red errors (JavaScript errors, blocked resources, CSP violations). In the Network tab, no request should fail (status 404 or 500), and AJAX responses should contain valid JSON, not PHP warnings mixed with the data.

HTML validation and Lighthouse

Check your HTML with the W3C validator at https://validator.w3.org/. Since your pages are generated by PHP on localhost, open a page, view its source (Ctrl+U), copy it and use the "Validate by Direct Input" tab. Fix the errors (unclosed tags, duplicate ids, missing alt attributes...). Then run Lighthouse (DevTools > Lighthouse tab, mode "Navigation") on your main pages for mobile and desktop, and use the report to improve performance, accessibility and best practices (image sizes, contrast, labels on form fields).

Tip: test in at least two browsers (for example Chrome and Firefox) and on a real phone connected to the same network, using your computer's IP address instead of localhost.

VIII. Optional: deploying online

Deployment is not required, but a public URL is a great addition to your README and your CV. Any PHP hosting with MySQL works the same way:
  1. Create the website and its database on the hosting service; note the database host, name, account and password.
  2. Import your .sql file in the phpMyAdmin of the host (remove the CREATE DATABASE line if the host imposes the name of the database).
  3. Upload the files, without the .git folder, into the public folder (often public_html).
  4. Create includes/config.local.php on the server only, with the database settings of the host and 'APP_DEBUG' => false.
  5. Change the passwords of the demo accounts, enable HTTPS, then run check_install.php (if the host gives a terminal) and the smoke test with the public address.
Warning: a public site is visited by bots that try common attacks within hours. Deploy only after the Lab 9 fixes, never with the demo passwords, and never with real personal data.

IX. Final presentation

The final presentation is a 10 to 15 minute demonstration of your project followed by questions. Every member must present the part they built and be able to explain its code: the evaluation is individual as well as collective. A suggested structure:

Part Duration Content
Introduction 1-2 min The problem, the target users, the team and who did what.
Architecture 2 min Database schema (tables and relations), folder structure, list of the web services.
Live demo 5-8 min A realistic user scenario that goes through the main CRUD services, authentication and AJAX. Each member demonstrates their own features. Show the responsive layout on a small screen.
Security and quality 1-2 min Main findings of the security audit and how they were fixed; testing done.
Conclusion 1 min Difficulties met, what you learned, possible improvements.

For Syaha, the live demo would follow one story: a visitor searches a trip under 20 000 DA, books it without an account; Amine registers, books a trip and cancels it; the admin logs in, confirms the booking of the visitor, adds a new trip with its photo, and reads the messages; finally, the team shows a CSRF attack page and a changed id being refused. Write the same kind of story for your project, with one part for each member.

Prepare the demo

  • Rehearse the full presentation at least once with a timer.
  • Prepare the demo data and the accounts in advance; log out of everything before you start.
  • Record a short backup video of the demo (screen recording) in case the network, the laptop or XAMPP fails on the day.
  • Have the project working on two laptops, and keep the code open in your editor to answer questions.
  • Zoom the browser and the editor (Ctrl and +) so the audience can read.

Questions you should be ready to answer
