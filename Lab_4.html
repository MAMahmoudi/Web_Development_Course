Lab 4: JavaScript: scripting CSS and form validation

Instructions

In Lab 2 and Lab 3 you built the HTML and CSS of the Syaha website. In this lab you bring it to life with JavaScript, step by step: first by scripting its CSS (menu, slider, animations, favourites, dialog), then by validating its forms. Each step is one small script of the demo; read it, run it, change it, then do the same in your team project.

I. JavaScript in a web page

Open the Syaha demo and try everything: the menu at phone width, the slider (arrows, dots, keyboard), the hearts and the "احجز الآن" buttons of the trip cards, the "back to top" button, the contact form and the login page. All of it is in the folder SRC/Labs/Lab_4+: one script per feature, plus one stylesheet, Interactions.css, for the elements that the scripts create or animate.

The scripts are loaded at the end of the <body>, after the HTML they work on. Each page only loads the scripts it needs. On the home page: 

    <!-- JavaScript (Lab 4) -->
    <script src="../Lab_4+/Drop_Down_Menu.js"></script>
    <script src="../Lab_4+/Image_Slider.js"></script>
    <script src="../Lab_4+/Scroll_Effects.js"></script>
    <script src="../Lab_4+/Read_More.js"></script>
    <script src="../Lab_4+/Favourites.js"></script>
    <script src="../Lab_4+/Booking.js"></script>
</body>
  • At the end of the body, the elements already exist when the script runs. A script in the <head> needs the defer attribute to wait for the HTML.
  • Each script is wrapped in a function that calls itself ((() => { ... })();). Its variables only exist inside, so two scripts can use the same names without conflict:
// Image_Slider.js
(() => {
  const Delay = 5000;   // only visible inside this function
  // ...
})();

// Read_More.js can also declare a constant named Delay: no conflict
  • Each script first checks that its elements exist (if (!Dialog) return;), because not every page has a slider or a dialog.
  • Progressive enhancement: everything that only makes sense with JavaScript (slider dots, "read more" and "book now" buttons, hearts, error messages) is created by the scripts. Without JavaScript the page still shows all its content.
Tip: keep the developer tools open (F12) while you work: the Console shows the errors of your scripts with their line number, and you can type JavaScript in it to test a selector, e.g. document.querySelectorAll(".Trip_Card").

III. Scripting CSS: styles or classes?

JavaScript can change the appearance of an element in several ways: 

const Slide = document.querySelector(".Slide");

// 1. the style property writes an inline style (style="..."): for values computed in JavaScript
Slide.style.transform = `translateX(-${Current * 100}%)`;

// 2. classList switches classes defined in the CSS: for states (open, active, visible...)
Menu.classList.add("active");
Menu.classList.remove("active");
Menu.classList.toggle("active");          // adds it if missing, removes it otherwise
Menu.classList.toggle("active", Open);    // adds it if Open is true, removes it otherwise
Menu.classList.contains("active");        // true or false

// 3. CSS custom properties can be set from JavaScript and used by the CSS
Text.style.setProperty("--Lines", 6);     // CSS: -webkit-line-clamp: var(--Lines, 6);

// 4. getComputedStyle reads the final value applied by all the CSS rules
getComputedStyle(Menu).display;           // "none" on a phone, "grid" on a desktop

The rule used in the whole demo: the CSS describes the states, JavaScript switches between them with classes. The menu is closed or active, a card is Visible, a heart is On; what these states look like is written in the stylesheets. Inline styles are kept for values that are computed while the page runs, such as the position of the slider.

Why: with classes, the look stays in the CSS where designers expect it, the transitions of the CSS animate the change for free, and the media queries of Lab 3 keep working.

IV. Step 1: the hamburger menu

In Lab 3, Nav_Bar_Responsive.css hides the menu on small screens and shows it when it has the class active. The script switches that class and keeps everything consistent: 

// Hamburger menu of the navigation bar (small screens, see Lab_3/Nav_Bar_Responsive.css).
// The menu is open when it has the class "active".
(() => {
  const Menu_Icon = document.getElementById("Menu_Icon_ID"),
    Nav_Bar_Menu = document.getElementById("Nav_Bar_Menu_ID"),
    Burger_Icon = document.getElementById("Burger_Icon_ID");

  if (!Menu_Icon || !Nav_Bar_Menu || !Burger_Icon) return;

  // the icon is a <div>: make it usable with the keyboard and by screen readers
  Menu_Icon.setAttribute("role", "button");
  Menu_Icon.setAttribute("tabindex", "0");
  Menu_Icon.setAttribute("aria-controls", "Nav_Bar_Menu_ID");

  function Set_Menu(Open) {
    Nav_Bar_Menu.classList.toggle("active", Open);
    Burger_Icon.className = Open ? "fas fa-times" : "fas fa-bars";
    Menu_Icon.setAttribute("aria-expanded", Open);
    Menu_Icon.setAttribute("aria-label", Open ? "إغلاق القائمة" : "فتح القائمة");
  }

  Set_Menu(false);

  Menu_Icon.addEventListener("click", () => {
    Set_Menu(!Nav_Bar_Menu.classList.contains("active"));
  });

  Menu_Icon.addEventListener("keydown", (event) => {
    if (event.key === "Enter" || event.key === " ") {
      event.preventDefault();
      Menu_Icon.click();
    }
  });

  // close the menu when a link is chosen, with Escape, or with a click outside the bar
  Nav_Bar_Menu.addEventListener("click", (event) => {
    if (event.target.closest("a")) Set_Menu(false);
  });

  document.addEventListener("keydown", (event) => {
    if (event.key === "Escape") Set_Menu(false);
  });

  document.addEventListener("click", (event) => {
    if (!event.target.closest?.(".Nav_Bar_Items")) Set_Menu(false);
  });

  // back to a desktop width (e.g. a tablet rotated): the hamburger disappears, so close the menu
  matchMedia("(min-width: 851px)").addEventListener("change", (event) => {
    if (event.matches) Set_Menu(false);
  });
})();
  • Set_Menu(Open) is the only place that opens or closes the menu: the class, the icon (bars or cross) and the aria-expanded attribute that tells screen readers the state. classList.toggle("active", Open) adds the class when Open is true and removes it otherwise.
  • The icon is a <div>; role="button" and tabindex="0" make it reachable with Tab, and the keydown listener opens it with Enter or Space.
  • The menu closes when a link is chosen, with Escape, or with a click anywhere outside the bar: event.target.closest(".Nav_Bar_Items") looks for the bar among the ancestors of the clicked element.
  • matchMedia watches a media query from JavaScript: when the screen becomes wide again, the menu is closed.
Try: in the console, type document.getElementById("Nav_Bar_Menu_ID").classList.toggle("active") at phone width: the menu opens without any click. The script does nothing more than that.

V. Step 2: the image slider

The six photos of the hero are placed side by side with left: 0%, 100%, 200%..., and the slider moves all of them with transform: translateX(). The arrows already exist in the HTML; the dots are created by the script: 

// Image slider of the home page hero: arrows, dots, keyboard, swipe and auto-play.
(() => {
  const Hero = document.querySelector(".Hero"),
    Slides = document.querySelectorAll(".Slide"),
    Previous_Btn = document.querySelector("#Slides_Previous_Btn"),
    Next_Btn = document.querySelector("#Slides_Next_Btn");

  if (!Hero || Slides.length === 0) return;

  const Delay = 5000,
    Reduced_Motion = matchMedia("(prefers-reduced-motion: reduce)").matches;
  let Current = 0,
    Timer = null;

  // place the slides side by side: 0%, 100%, 200%...
  Slides.forEach((Slide, index) => {
    Slide.style.left = index * 100 + "%";
  });

  // one dot per slide, named after the photo (its alt text)
  const Dots = document.createElement("div");
  Dots.className = "Slider_Dots";
  Slides.forEach((Slide, index) => {
    const Dot = document.createElement("button");
    Dot.type = "button";
    Dot.className = "Slider_Dot";
    Dot.setAttribute("aria-label", Slide.alt);
    Dot.addEventListener("click", () => {
      Go_To(index);
      Restart();
    });
    Dots.appendChild(Dot);
  });
  Hero.appendChild(Dots);

  function Go_To(index) {
    // (index + length) % length keeps the index between 0 and length - 1, even when index is -1
    Current = (index + Slides.length) % Slides.length;
    Slides.forEach((Slide) => {
      Slide.style.transform = `translateX(-${Current * 100}%)`;
    });
    Dots.querySelectorAll(".Slider_Dot").forEach((Dot, i) => {
      Dot.classList.toggle("Active", i === Current);
      Dot.setAttribute("aria-current", i === Current);
    });
  }

  const Next = () => Go_To(Current + 1),
    Previous = () => Go_To(Current - 1);

  function Start() {
    if (!Reduced_Motion && Timer === null) Timer = setInterval(Next, Delay);
  }

  function Stop() {
    clearInterval(Timer);
    Timer = null;
  }

  function Restart() {
    Stop();
    Start();
  }

  // the arrows are <i> icons: give them a role, a name and keyboard access
  [
    [Next_Btn, Next, "الصورة التالية"],
    [Previous_Btn, Previous, "الصورة السابقة"],
  ].forEach(([Button, Action, Label]) => {
    if (!Button) return;
    Button.setAttribute("role", "button");
    Button.setAttribute("tabindex", "0");
    Button.setAttribute("aria-label", Label);
    Button.addEventListener("click", () => {
      Action();
      Restart();
    });
    Button.addEventListener("keydown", (event) => {
      if (event.key === "Enter" || event.key === " ") {
        event.preventDefault();
        Button.click();
      }
    });
  });

  // keyboard arrows, unless the visitor is typing in a field
  document.addEventListener("keydown", (event) => {
    if (event.target.closest?.("input, textarea, select")) return;
    if (event.key === "ArrowRight") Next_Btn?.click();
    if (event.key === "ArrowLeft") Previous_Btn?.click();
  });

  // swipe on touch screens
  let Touch_Start_X = null;
  Hero.addEventListener("touchstart", (event) => {
    Touch_Start_X = event.touches[0].clientX;
  }, { passive: true });
  Hero.addEventListener("touchend", (event) => {
    if (Touch_Start_X === null) return;
    const Distance = event.changedTouches[0].clientX - Touch_Start_X;
    if (Math.abs(Distance) > 50) {
      Distance < 0 ? Next() : Previous();
      Restart();
    }
    Touch_Start_X = null;
  });

  // pause while the mouse is over the hero or the tab is hidden
  Hero.addEventListener("mouseenter", Stop);
  Hero.addEventListener("mouseleave", Start);
  document.addEventListener("visibilitychange", () => (document.hidden ? Stop() : Start()));

  Go_To(0);
  Start();
})();

  • Go_To(index) is the heart of the slider: (index + length) % length wraps around, so "previous" on the first photo goes to the last one (in JavaScript -1 % 6 is -1, hence the + length). The transition: 1s of Slider.css animates the movement.
  • Auto-play uses setInterval; clearInterval stops it while the mouse is over the hero (mouseenter/mouseleave) or the tab is hidden (visibilitychange). Every manual action restarts the timer.
  • The dots are <button> elements: they can be focused and clicked with the keyboard. The active dot has the class Active.
  • Touch events (touchstart, touchend) give a swipe: if the finger moved more than 50px, go to the next or previous photo.
  • prefers-reduced-motion is a setting of the visitor's system: auto-play is disabled when they asked for less motion.

VI. Step 3: effects linked to scrolling

Three effects depend on the scroll position: the navigation bar gets smaller, the cards fade in when they appear on the screen, and a "back to top" button shows up. The script also writes the current year in the footer. 

// Effects linked to scrolling, shared by every page that has the navigation bar:
// smaller navigation bar, cards appearing on scroll, "back to top" button and current year in the footer.
(() => {
  const Reduced_Motion = matchMedia("(prefers-reduced-motion: reduce)").matches;

  // 1. the navigation bar gets the class "Scrolled" once the page is scrolled
  const Nav_Bar = document.querySelector(".Nav_Bar_Items");
  const Update_Nav_Bar = () => Nav_Bar?.classList.toggle("Scrolled", scrollY > 50);

  // 2. cards fade in when they enter the screen
  const Cards = document.querySelectorAll(
    ".Destination_Item, .Destination_Item_Reverse, .Trip_Card, .Feature, .Service_Card, .Team_Card, .Contact_Info_Item"
  );
  if (!Reduced_Motion && "IntersectionObserver" in window) {
    const Observer = new IntersectionObserver((entries) => {
      entries.forEach((entry) => {
        if (!entry.isIntersecting) return;
        const Card = entry.target;
        Card.classList.add("Visible");
        Observer.unobserve(Card);
        // once visible, remove the classes so that the card's own :hover transform works again
        // (transitionend also bubbles up from the card's children: only react to the card itself)
        Card.addEventListener("transitionend", function Done(event) {
          if (event.target !== Card) return;
          Card.classList.remove("Reveal", "Visible", "Delay_1", "Delay_2", "Delay_3");
          Card.removeEventListener("transitionend", Done);
        });
      });
    }, { threshold: 0.15 });

    Cards.forEach((Card) => {
      // the class is added by JavaScript: without JavaScript, the cards stay visible
      Card.classList.add("Reveal");
      // cards of the same row appear one after the other
      const Position = [...Card.parentElement.children].indexOf(Card) % 4;
      if (Position > 0) Card.classList.add("Delay_" + Position);
      Observer.observe(Card);
    });
  }

  // 3. "back to top" button, created here because it is only useful with JavaScript
  const Top_Btn = document.createElement("button");
  Top_Btn.type = "button";
  Top_Btn.className = "Back_To_Top";
  Top_Btn.setAttribute("aria-label", "العودة إلى أعلى الصفحة");
  Top_Btn.innerHTML = '<i class="fa-solid fa-arrow-up"></i>';
  Top_Btn.addEventListener("click", () => scrollTo({ top: 0 }));
  document.body.appendChild(Top_Btn);
  const Update_Top_Btn = () => Top_Btn.classList.toggle("Shown", scrollY > 600);

  // 4. the copyright always shows the current year
  const Copyright = document.querySelector(".Footer_Copyright");
  if (Copyright) Copyright.textContent = Copyright.textContent.replace(/\d{4}/, new Date().getFullYear());

  // the scroll event fires very often: keep the work done here small (two class toggles).
  // passive: true tells the browser that we never call preventDefault(), so scrolling stays smooth
  addEventListener("scroll", () => {
    Update_Nav_Bar();
    Update_Top_Btn();
  }, { passive: true });

  Update_Nav_Bar();
  Update_Top_Btn();
})();

VII. Step 4: "read more"

The texts of the trips and destinations are long. The script cuts them after a few lines and adds a button that shows the rest: 

// "Read more" for long texts: the text is cut after a few lines and a button shows the rest.
(() => {
  const Targets = [
    [".Trip_Card p", 6],
    [".Destination_Text p", 10],
  ];

  function Setup() {
    Targets.forEach(([Selector, Lines]) => {
      document.querySelectorAll(Selector).forEach((Text) => {
        if (Text.nextElementSibling?.classList.contains("Read_More_Btn")) return;

        Text.style.setProperty("--Lines", Lines);
        Text.classList.add("Clamped");
        // short texts fit in the lines: nothing to hide
        if (Text.scrollHeight <= Text.clientHeight + 1) {
          Text.classList.remove("Clamped");
          return;
        }

        const Button = document.createElement("button");
        Button.type = "button";
        Button.className = "Read_More_Btn";
        Button.textContent = "اقرأ المزيد";
        Button.setAttribute("aria-expanded", "false");
        Button.addEventListener("click", (event) => {
          event.stopPropagation();
          const Open = Text.classList.toggle("Clamped") === false;
          Button.textContent = Open ? "عرض أقل" : "اقرأ المزيد";
          Button.setAttribute("aria-expanded", Open);
        });
        Text.after(Button);
      });
    });
  }

  // wait for the web font: the number of lines depends on it
  if (document.fonts) document.fonts.ready.then(Setup);
  else addEventListener("load", Setup);
})();

VIII. Step 5: favourites saved in the browser

A heart on each trip card adds it to the visitor's favourites. The list survives a reload and is shared by the home page and the services page, because it is stored with localStorage: 

// Favourite trips: a heart on each trip card, remembered in localStorage (shared by the home and services pages).
(() => {
  const Key = "Syaha_Favourites";

  // localStorage only stores strings: the list is saved as JSON.
  // It can be unavailable (private browsing, blocked storage), hence the try/catch.
  function Load() {
    try {
      return JSON.parse(localStorage.getItem(Key)) || [];
    } catch {
      return [];
    }
  }

  function Save(List) {
    try {
      localStorage.setItem(Key, JSON.stringify(List));
    } catch {
      // the favourites will only last until the page is closed
    }
  }

  let Favourites = Load();

  // small message at the bottom of the screen, hidden after 2.5 s
  const Toast = document.createElement("div");
  Toast.className = "Toast";
  Toast.setAttribute("role", "status");
  document.body.appendChild(Toast);
  let Toast_Timer;

  function Show_Toast(Text) {
    Toast.textContent = Text;
    Toast.classList.add("Shown");
    clearTimeout(Toast_Timer);
    Toast_Timer = setTimeout(() => Toast.classList.remove("Shown"), 2500);
  }

  const Renders = [];

  document.querySelectorAll(".Trip_Card").forEach((Card) => {
    const Title = Card.querySelector("h4").textContent.trim(),
      Frame = Card.querySelector(".Trip_Image");

    const Button = document.createElement("button");
    Button.type = "button";
    Button.className = "Favourite_Btn";

    function Render() {
      const On = Favourites.includes(Title);
      Button.innerHTML = `<i class="${On ? "fa-solid" : "fa-regular"} fa-heart"></i>`;
      Button.classList.toggle("On", On);
      Button.setAttribute("aria-pressed", On);
      Button.setAttribute("aria-label", On ? `إزالة ${Title} من المفضلة` : `إضافة ${Title} إلى المفضلة`);
    }

    Button.addEventListener("click", (event) => {
      event.stopPropagation();
      if (Favourites.includes(Title)) {
        Favourites = Favourites.filter((Item) => Item !== Title);
        Show_Toast(`تمت إزالة «${Title}» من المفضلة`);
      } else {
        Favourites.push(Title);
        Show_Toast(`تمت إضافة «${Title}» إلى المفضلة`);
      }
      Save(Favourites);
      Render();
    });

    Render();
    Renders.push(Render);
    Frame.appendChild(Button);
  });

  // the favourites were changed in another tab: update this one
  addEventListener("storage", (event) => {
    if (event.key !== Key) return;
    Favourites = Load();
    Renders.forEach((Render) => Render());
  });
})();

IX. Step 6: a modal dialog to book a trip

The "احجز الآن" button of each card opens a booking form in a modal dialog. The <dialog> element is written in the HTML of the home and services pages, after the trips section:

(() => {
  const Dialog = document.getElementById("Booking_Dialog");
  if (!Dialog) return;

  const Form = Dialog.querySelector("form"),
    Trip = Form.querySelector("#Booking_Trip"),
    People = Form.querySelector("#Booking_People"),
    Departure = Form.querySelector("#Booking_Date"),
    Total = Form.querySelector("#Booking_Total"),
    Message = Form.querySelector("#Booking_Message"),
    Fields = Form.querySelectorAll("input, select");

  // without this, the browser would check the form itself and never fire "submit" while a field is invalid,
  // so our Arabic messages would never be set. We call reportValidity() ourselves instead.
  Form.noValidate = true;

  // the earliest departure is in 3 days: the min attribute is computed when the page loads
  const Earliest = new Date();
  Earliest.setDate(Earliest.getDate() + 3);
  const Pad = (n) => String(n).padStart(2, "0");
  Departure.min = `${Earliest.getFullYear()}-${Pad(Earliest.getMonth() + 1)}-${Pad(Earliest.getDate())}`;

  // one Arabic message per validity state (the browser would show its own messages in its own language)
  const Messages = {
    valueMissing: () => "هذا الحقل إجباري.",
    typeMismatch: () => "الصيغة غير صحيحة.",
    tooShort: (Field) => `أدخل ${Field.minLength} أحرف على الأقل.`,
    rangeUnderflow: (Field) =>
      Field.type === "date" ? "يجب أن يكون تاريخ الانطلاق بعد 3 أيام على الأقل." : `القيمة الدنيا هي ${Field.min}.`,
    rangeOverflow: (Field) => `القيمة القصوى هي ${Field.max}.`,
    badInput: () => "القيمة غير صحيحة.",
  };

  function Explain(Field) {
    Field.setCustomValidity(""); // forget the previous message, then ask the browser again
    if (Field.validity.valid) return true;
    const State = Object.keys(Messages).find((Name) => Field.validity[Name]);
    Field.setCustomValidity(State ? Messages[State](Field) : "القيمة غير صحيحة.");
    return false;
  }

  // the total is computed from the price stored in the chosen <option data-price="...">
  const Money = new Intl.NumberFormat("fr-DZ");
  function Update_Total() {
    const Price = Number(Trip.selectedOptions[0]?.dataset.price || 0),
      Count = Number(People.value) || 0;
    Total.value = `${Money.format(Price * Count)} دج`;
  }

  Fields.forEach((Field) =>
    Field.addEventListener("input", () => {
      Explain(Field);
      Update_Total();
    })
  );

  let Close_Timer;

  function Open(Title) {
    clearTimeout(Close_Timer);
    Form.reset();
    Message.textContent = "";
    Fields.forEach((Field) => Field.setCustomValidity(""));
    // preselect the trip of the card that was clicked
    const Option = [...Trip.options].find((O) => O.textContent.trim().startsWith(Title));
    if (Option) Trip.value = Option.value;
    Update_Total();
    Dialog.showModal();
    Form.querySelector("#Booking_Name").focus();

  // From Lab 6, the server writes a link to the booking page (it works without JavaScript):
  // with JavaScript, the same link opens the dialog instead.
  document.querySelectorAll(".Trip_Card").forEach((Card) => {

      Button = document.createElement("button");
      Button.type = "button";
      Button.className = "Book_Btn";
      Button.innerHTML = '<i class="fa-solid fa-calendar-check"></i> احجز الآن';
      Card.appendChild(Button);
    }
    Button.addEventListener("click", (event) => {
      event.preventDefault();
      Open(Card.querySelector("h4").textContent.trim());
    });
  });

  Form.querySelector("#Booking_Cancel").addEventListener("click", () => Dialog.close());

  // a click on the dark backdrop reaches the <dialog> itself, not the form inside it
  Dialog.addEventListener("click", (event) => {
    if (event.target === Dialog) Dialog.close();

    if (!All_Valid) {

    Message.textContent = `تم تسجيل حجزكم لرحلة ${Trip.selectedOptions[0].textContent.trim().split(" (")[0]} ` +
      `لـ ${People.value} مسافر(ين) يوم ${Date_Text}. المجموع: ${Total.value}`;
    Close_Timer = setTimeout(() => Dialog.close(), 3500);
  });
})();
The dialog part of the script:
  • Dialog.showModal() opens the dialog above the page, makes the rest of the page inactive, and draws the ::backdrop. Escape closes it natively; Dialog.close() closes it from the "إلغاء" button.
  • A click on the dark backdrop has the <dialog> itself as event.target (the form covers the inside of the dialog): that is how the script detects it.

X. Form validation: why and where

Before sending data to the server, check it in the browser: the visitor sees their mistakes at once, next to the field, without waiting for a reply. But client-side validation is only for comfort. Anybody can switch JavaScript off, edit the HTML with the developer tools, or send a request without using the form at all. The server must check everything again (Lab 6).

The first level costs nothing: HTML attributes. The browser checks them before sending the form and shows its own messages. 

<input type="text" name="name" minlength="3" required>
<input type="email" name="email" required>
<input type="tel" name="phone" pattern="0[5-7][0-9]{8}">
<input type="date" name="date" min="2025-01-01" required>
<input type="number" name="people" min="1" max="10" value="1" required>
<select name="trip" required>
    <option value="">Choose a trip</option>  <!-- value="" counts as empty for required -->
    ...
</select>
AttributeChecks that
requiredthe field is not empty
type="email", "url", "number", "date"the value has the right format (and shows the right keyboard on phones)
minlength / maxlengththe number of characters
min / max / stepthe range of a number or a date
patternthe value matches a regular expression (the whole value, no need for ^ and $)

Three levels are used in the demo, from the simplest to the most flexible: the booking form uses the attributes and the browser's Constraint Validation API (Step 7); the contact form and the login form use their own rules and messages (Steps 8 and 9).

XI. Step 7: the Constraint Validation API (booking form)

Each field of a form has a validity object that tells which constraint fails:
Property of field.validityTrue when
valueMissinga required field is empty
typeMismatchthe value is not a valid e-mail / URL
patternMismatchthe value does not match pattern
tooShort / tooLongminlength / maxlength not respected
rangeUnderflow / rangeOverflowbelow min / above max
badInputthe browser cannot understand the value (letters in a number field)
customErrora message was set with setCustomValidity()
valideverything is fine
The booking script uses it to replace the browser's messages (written in the language of the browser) with Arabic messages:

XII. Step 8: custom messages under each field (contact form)

The browser's bubbles disappear after a few seconds and only show one message at a time. The contact form shows its own messages, one under each field, and checks rules that HTML attributes cannot express: 

// Validation of the contact form (Contact_Us.html): one message under each field, checked on submit,
// then again while the visitor corrects the field. The server must validate again (Lab 6).
(() => {
  const Form = document.querySelector(".Contact_Us_Container form");
  if (!Form) return;

  const Max_Message = 500;

  // [field, test returning an error message or "" when the value is valid]
  const Rules = [
    ["#Name", (v) => (v.length < 3 ? "الرجاء إدخال الإسم الكامل (3 أحرف على الأقل)." : "")],
    ["#Email", (v) =>
      v === "" ? "الرجاء إدخال البريد الإلكتروني."
        : !/^[^\s@]+@[^\s@]+\.[a-z]{2,}$/i.test(v) ? "البريد الإلكتروني غير صحيح." : ""],
    // optional, but if given it must be an Algerian mobile number: 05, 06 or 07 followed by 8 digits
    ["#Phone", (v) => (v !== "" && !/^0[5-7][0-9]{8}$/.test(v) ? "رقم الهاتف يجب أن يكون من الشكل 05XXXXXXXX." : "")],
    ["#Subject", (v) => (v === "" ? "الرجاء اختيار موضوع." : "")],
    ["#Message", (v) => (v.length < 20 ? "الرسالة قصيرة جداً (20 حرفاً على الأقل)." : "")],
  ].map(([Selector, Test]) => [Form.querySelector(Selector), Test]);

  // our own messages replace the browser's bubbles
  Form.noValidate = true;

  // a message element after each field; the server (Lab 6) may already have written one: reuse it
  Rules.forEach(([Field]) => {
    let Error = Field.nextElementSibling;
    if (!Error || !Error.classList.contains("Field_Error")) {
      Error = document.createElement("small");
      Error.className = "Field_Error";
      Field.after(Error);
    }
    Error.id = Field.id + "_Error";
    Error.setAttribute("aria-live", "polite");
    Field.setAttribute("aria-describedby", Error.id);
  });

  // characters left in the message
  const Message = Form.querySelector("#Message");
  Message.maxLength = Max_Message;
  const Counter = document.createElement("small");
  Counter.className = "Char_Counter";
  Message.parentElement.insertBefore(Counter, Message.nextElementSibling.nextElementSibling);
  const Update_Counter = () => {
    Counter.textContent = `${Message.value.length} / ${Max_Message}`;
  };
  Message.addEventListener("input", Update_Counter);
  Update_Counter();

  function Check(Field, Test) {
    const Error = Test(Field.value.trim());
    Field.nextElementSibling.textContent = Error;
    Field.classList.toggle("Invalid", Error !== "");
    Field.classList.toggle("Valid", Error === "" && Field.value.trim() !== "");
    Field.setAttribute("aria-invalid", Error !== "");
    return Error === "";
  }

  // after a field has been left once, check it at each keystroke
  Rules.forEach(([Field, Test]) => {
    Field.addEventListener("blur", () => {
      Field.dataset.touched = "yes";
      Check(Field, Test);
    });
    Field.addEventListener("input", () => {
      if (Field.dataset.touched) Check(Field, Test);
    });
  });

  const Success = document.createElement("p");
  Success.className = "Form_Success";
  Success.setAttribute("role", "status");
  Form.appendChild(Success);

  Form.addEventListener("submit", (event) => {
    event.preventDefault();
    Success.textContent = "";
    const Results = Rules.map(([Field, Test]) => Check(Field, Test));
    if (Results.includes(false)) {
      Rules[Results.indexOf(false)][0].focus();
      return;
    }
    // with a back end (Lab 5), the form has a real action: send it; the server checks it again
    const Action = Form.getAttribute("action");
    if (Action && Action !== "#") {
      Form.submit();
      return;
    }
    // static demo (Labs 2 to 4): nothing is sent, show a confirmation
    Success.textContent = "شكراً لكم! تم استلام رسالتكم وسنرد عليكم في أقرب وقت.";
    Form.reset();
    Rules.forEach(([Field]) => {
      Field.classList.remove("Valid");
      delete Field.dataset.touched;
    });
    Update_Counter();
  });
})();

XIV. Regular expressions

The rules of the forms use regular expressions, patterns that a text must match, written between slashes and tested with .test(text):
SymbolMeaningExample
