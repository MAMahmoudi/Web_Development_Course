Lab 4: JavaScript form validation

Instructions

In this lab, you will validate the forms of your team project before their data is sent to the server.
You will start with the validation built into HTML5 (required, type, pattern, min/max, ...), then control it from JavaScript with the Constraint Validation API, and finally write your own validation with clear error messages, regular expressions (emails, Algerian phone numbers), password rules and real-time feedback.
Before you start, read the lecture JavaScript form validation and try the demo form (its code: Form_Validation.js, Form_Validation.css).

I. Why validate forms, and where?

Every web service of your project (create, update, search, login, ...) receives data from a form. Validating this data means checking that it is present, has the right format (email, phone, date, ...) and respects your business rules (the user is at least 18, the quantity is between 1 and 10, the two passwords are the same, ...).

  • Client-side validation (HTML5 + JavaScript, this lab) runs in the browser. Its goal is the user experience: the user sees the error immediately, next to the field, without waiting for a page reload.
  • Server-side validation (PHP, later labs) runs on the server. Its goal is security and data integrity.
Warning: Client-side validation never replaces server-side validation. Anyone can disable JavaScript, remove the required attribute with the DevTools, or send a request directly to your PHP script with tools such as Postman or curl. The browser is under the user's control, so your PHP code must check every value again before using it (and use prepared statements for SQL; see the Security lecture).

For example, the same email and phone rules on the server side will look like this:

<?php
$errors = [];
$email = trim($_POST["Email"] ?? "");
$phone = trim($_POST["Phone_Number"] ?? "");

if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors["Email"] = "Email is not valid";
}
if (!preg_match('/^0[5-7][0-9]{8}$/', $phone)) {
    $errors["Phone_Number"] = "Phone number is not valid";
}

if (count($errors) > 0) {
    http_response_code(422);   // Unprocessable Content
    // ... display the form again with the error messages
}

II. HTML5 constraint validation

Before writing any JavaScript, use the right input types and attributes. The browser then refuses to submit the form and shows a message when a constraint is not respected. On phones, the type also displays the appropriate keyboard (a number pad for tel, an "@" key for email).

Attribute Meaning Example
required The field cannot be empty <input name="Name" required>
type The value must have the format of the type (email, url, number, date, ...) <input type="email">
minlength / maxlength Minimum / maximum number of characters <input minlength="3" maxlength="30">
min / max / step Range and step of numbers and dates <input type="number" min="1" max="10" step="1">
pattern The value must match a regular expression (the whole value) <input type="tel" pattern="0[5-7][0-9]{8}"> 
<form id="Signup_Form" action="signup.php" method="POST">
  <label for="Full_Name">Full name</label>
  <input type="text" id="Full_Name" name="Full_Name" required minlength="3" maxlength="50" />

  <label for="Email">Email</label>
  <input type="email" id="Email" name="Email" required autocomplete="email" />

  <label for="Phone_Number">Phone number (05/06/07 followed by 8 digits)</label>
  <input type="tel" id="Phone_Number" name="Phone_Number" required
         pattern="0[5-7][0-9]{8}" maxlength="10" inputmode="numeric"
         title="Example: 0555123456" />

  <label for="Quantity">Number of tickets</label>
  <input type="number" id="Quantity" name="Quantity" min="1" max="10" value="1" />

  <label for="Birthdate">Birthdate</label>
  <input type="date" id="Birthdate" name="Birthdate" required />

  <button type="submit">Sign up</button>
</form>

The file Phone.html is a minimal working example: a tel input with required and pattern="[0]{1}[5-7]{1}[0-9]{8}" (the same rule as 0[5-7][0-9]{8}). Open it and try to submit "0812345678" or "055512".

You can style valid and invalid fields with CSS pseudo-classes. :invalid applies immediately (even before the user has typed anything), so prefer :user-invalid, which applies only after the user has interacted with the field: 

input:user-invalid {
  border: 2px solid red;
}

input:user-valid {
  border: 2px solid green;
}
Tip: The default browser messages depend on the browser and its language, and their look cannot be styled. When you display your own messages with JavaScript (sections III to VII), add the novalidate attribute to the <form>: the HTML5 constraints still work (and you can read them from JavaScript), but the browser no longer shows its own bubbles.

III. The Constraint Validation API

Every form field has properties and methods that give JavaScript access to the HTML5 validation:

Property / method Description
input.checkValidity() Returns true if the field respects all its constraints (also exists on the form: form.checkValidity())
input.reportValidity() Same as checkValidity(), and also shows the browser's message to the user
input.validationMessage The message the browser would display (in the browser's language)
input.setCustomValidity(message) Marks the field as invalid with your own message; setCustomValidity("") marks it valid again
input.validity A ValidityState object with one boolean per constraint (see below)

The properties of input.validity tell you which constraint failed:

  • valueMissing: a required field is empty
  • typeMismatch: the value does not match the type (email, url)
  • patternMismatch: the value does not match the pattern
  • tooShort / tooLong: minlength / maxlength not respected
  • rangeUnderflow / rangeOverflow: smaller than min / larger than max
  • stepMismatch: the value does not respect step
  • badInput: the browser cannot convert the input (letters in a number field)
  • customError: a message was set with setCustomValidity()
  • valid: true when none of the above is true

Example: a custom message for the phone number

const phone = document.querySelector("#Phone_Number");

const updatePhoneMessage = () => {
  phone.setCustomValidity("");   // reset first, otherwise the field stays invalid forever

  if (phone.validity.valueMissing) {
    phone.setCustomValidity("Please enter your phone number.");
  } else if (phone.validity.patternMismatch) {
    phone.setCustomValidity("An Algerian mobile number starts with 05, 06 or 07, followed by 8 digits.");
  }
};

phone.addEventListener("input", updatePhoneMessage);
updatePhoneMessage();   // set the right message when the page loads
Tip: Always call setCustomValidity("") before testing again. As long as a custom message is set, validity.customError is true and the field is invalid, even if the user has corrected the value.

IV. Custom validation with error messages

The demo form uses a pattern with two helper functions: setErrorFor(input, message) marks a field as wrong and displays a message, and setSuccessFor(input) marks it as correct. The demo writes all the messages in a single <small> under the button. It is clearer for the user to show each message next to its field, so we wrap every field in a .Form_Control with its own <small>: 

<form id="Signup_Form" action="signup.php" method="POST" novalidate>
  <div class="Form_Control">
    <label for="Full_Name">Full name</label>
    <input type="text" id="Full_Name" name="Full_Name" required aria-describedby="Full_Name_Error" />
    <small class="Error_Message" id="Full_Name_Error" aria-live="polite"></small>
  </div>

  <div class="Form_Control">
    <label for="Email">Email</label>
    <input type="email" id="Email" name="Email" required aria-describedby="Email_Error" />
    <small class="Error_Message" id="Email_Error" aria-live="polite"></small>
  </div>

  <!-- ... same structure for Phone_Number, Password, Confirm_Password, Birthdate ... -->

  <button type="submit">Sign up</button>
</form>
        
.Form_Control {
  display: flex;
  flex-direction: column;
  margin-bottom: 1rem;
}

.Form_Control input.error {
  border: 2px solid red;
  background-color: rgb(255 0 0 / 0.1);
}

.Form_Control input.success {
  border: 2px solid green;
  background-color: rgb(0 255 0 / 0.1);
}

.Error_Message {
  color: red;
  min-height: 1.2em;   /* reserve space so the form does not jump */
}
        
const setErrorFor = (input, message) => {
  const control = input.closest(".Form_Control");
  control.querySelector(".Error_Message").textContent = message;
  input.classList.remove("success");
  input.classList.add("error");
  input.setAttribute("aria-invalid", "true");   // announced by screen readers
};

const setSuccessFor = (input) => {
  const control = input.closest(".Form_Control");
  control.querySelector(".Error_Message").textContent = "";
  input.classList.remove("error");
  input.classList.add("success");
  input.removeAttribute("aria-invalid");
};

Use textContent (not innerHTML) to display messages: it inserts plain text, so a value typed by the user can never be interpreted as HTML. Notice also that, unlike the demo, the message is replaced each time, not appended with +=; otherwise the same error would be repeated every time the user clicks the button.

V. Regular expressions for emails and Algerian phone numbers

A regular expression (regex) describes a text pattern. In JavaScript it is written between slashes, and its test() method returns true if a string matches. The most useful symbols are:

Symbol Meaning
^ and $ Start and end of the string (without them, the pattern can match anywhere inside the value)
[5-7], [a-zA-Z] One character from the set or range
[^0-9] One character that is not in the set
\d, \w, \s A digit, a "word" character (letter, digit or _), a white space
. Any character (write \. for a real dot)
+, *, ? One or more, zero or more, zero or one of the previous item
{8}, {2,}, {3,30} Exactly 8, at least 2, between 3 and 30 of the previous item
(...), a|b A group, and "a or b" 
// Algerian mobile number: 0, then 5, 6 or 7, then exactly 8 digits (10 digits in total)
const PHONE_REGEX = /^0[5-7][0-9]{8}$/;

// Optional: also accept the international format +213 5x xx xx xx
const PHONE_INTL_REGEX = /^(0|\+213)[5-7][0-9]{8}$/;

// Email: characters before @, a domain, a dot, and an extension of at least 2 letters
const EMAIL_REGEX = /^[\w.+-]+@[\w-]+(\.[\w-]+)*\.[a-zA-Z]{2,}$/;

// Username: 3 to 20 letters, digits or underscores
const USERNAME_REGEX = /^\w{3,20}$/;

const isPhoneNumber = (value) => PHONE_REGEX.test(value);
const isEmail = (value) => EMAIL_REGEX.test(value);

console.log(isPhoneNumber("0555123456"));   // true
console.log(isPhoneNumber("0812345678"));   // false: 08 is not a mobile prefix
console.log(isPhoneNumber("055512345"));    // false: only 9 digits
console.log(isEmail("student@ensia.edu.dz")); // true
console.log(isEmail("student@ensia"));        // false: no extension
Tip: In the HTML pattern attribute, do not write the slashes nor ^ and $: the browser always compares the whole value. So /^0[5-7][0-9]{8}$/ in JavaScript becomes pattern="0[5-7][0-9]{8}" in HTML. You can test your regular expressions on regex101.com (choose the ECMAScript flavor). No regex can check that an email address really exists: only sending a confirmation email can.

VI. Password strength and confirmation (and other rules)

1. Password strength

Instead of one long and unreadable regex, test each rule separately. This lets you tell the user exactly what is missing and display a strength meter. Add a <meter> under the password field: 

<div class="Form_Control">
  <label for="Password">Password</label>
  <input type="password" id="Password" name="Password" required minlength="8" autocomplete="new-password" />
  <meter id="Password_Strength" min="0" max="5" low="3" high="4" optimum="5" value="0"></meter>
  <small class="Error_Message"></small>
</div>
        
const PASSWORD_RULES = [
  { regex: /.{8,}/, message: "at least 8 characters" },
  { regex: /[a-z]/, message: "a lowercase letter" },
  { regex: /[A-Z]/, message: "an uppercase letter" },
  { regex: /[0-9]/, message: "a digit" },
  { regex: /[^A-Za-z0-9]/, message: "a special character (!, @, #, ...)" },
];

// Returns the list of rules that the password does not respect yet
const getMissingRules = (password) =>
  PASSWORD_RULES.filter((rule) => !rule.regex.test(password)).map((rule) => rule.message);

const passwordInput = document.querySelector("#Password");
const strengthMeter = document.querySelector("#Password_Strength");

passwordInput.addEventListener("input", () => {
  const missing = getMissingRules(passwordInput.value);
  strengthMeter.value = PASSWORD_RULES.length - missing.length;   // 0 (weak) to 5 (strong)
});

const validatePassword = (value) => {
  if (value === "") return "Password cannot be blank";
  const missing = getMissingRules(value);
  if (missing.length > 0) return `Password must contain ${missing.join(", ")}`;
  return "";   // empty string = no error
};

2. Password confirmation

const validateConfirmPassword = (value) => {
  if (value === "") return "Please confirm your password";
  if (value !== passwordInput.value) return "Passwords do not match";
  return "";
};
Tip: Do not trim() passwords: a space can be a valid character of a password. On the server, never store the password itself; store its hash with PHP's password_hash() and check it with password_verify().

3. Business rules: the minimum age

Some rules cannot be written with HTML attributes because they depend on the current date or on another field. The demo checks that the birthdate is not in the future and that the user is at least 18. Comparing dates is more precise than dividing milliseconds by 365 days (which ignores leap years): 

const validateBirthdate = (value) => {
  if (value === "") return "Birthdate cannot be blank";

  const birthdate = new Date(value);
  const today = new Date();
  if (birthdate > today) return "You can't be born in the future";

  // The date of the 18th birthday
  const adultDate = new Date(birthdate);
  adultDate.setFullYear(birthdate.getFullYear() + 18);
  if (adultDate > today) return "You must be 18 years old or older";

  return "";
};

VII. Real-time validation and submission

The demo validates only when the button is clicked. Users prefer immediate feedback, but showing "Email is not valid" after the first letter is annoying. A good compromise:

  • on blur (the user leaves the field): validate it and remember that it was "touched";
  • on input (each key typed): re-validate only fields that were already touched, so the error disappears as soon as the value is correct;
  • on submit: validate every field, and cancel the submission with event.preventDefault() only if at least one field is invalid.

Listen to the submit event of the form rather than the click event of the button: submit also fires when the user presses Enter in a field. 

const form = document.querySelector("#Signup_Form");

// One validation function per field name. Each returns "" when the value is valid,
// otherwise the error message to display.
const validators = {
  Full_Name: (value) => (value.trim().length < 3 ? "Name must contain at least 3 characters" : ""),
  Email: (value) => {
    if (value.trim() === "") return "Email cannot be blank";
    return isEmail(value.trim()) ? "" : "Email is not valid";
  },
  Phone_Number: (value) => {
    if (value.trim() === "") return "Phone number cannot be blank";
    return isPhoneNumber(value.trim()) ? "" : "Use 05, 06 or 07 followed by 8 digits";
  },
  Password: validatePassword,
  Confirm_Password: validateConfirmPassword,
  Birthdate: validateBirthdate,
};

const validateField = (input) => {
  const message = validators[input.name](input.value);
  if (message === "") {
    setSuccessFor(input);
    return true;
  }
  setErrorFor(input, message);
  return false;
};

const fields = Object.keys(validators).map((name) => form.elements[name]);

fields.forEach((input) => {
  input.addEventListener("blur", () => {
    input.dataset.touched = "true";
    validateField(input);
  });

  input.addEventListener("input", () => {
    if (input.dataset.touched === "true") validateField(input);
  });
});

// When the password changes, the confirmation must be checked again
form.elements.Password.addEventListener("input", () => {
  const confirm = form.elements.Confirm_Password;
  if (confirm.dataset.touched === "true") validateField(confirm);
});

form.addEventListener("submit", (event) => {
  // map() (not every()) so that ALL the fields show their message, not just the first one
  const results = fields.map(validateField);

  if (results.includes(false)) {
    event.preventDefault();                 // stay on the page
    form.querySelector(".error").focus();   // help the user find the first error
  }
  // otherwise the form is sent normally to signup.php, which validates everything again
});
Tip: You can combine both worlds: keep the HTML5 attributes (required, pattern, ...) on your inputs, and inside validateField use input.checkValidity() and input.validity (section III) to choose the message. This way the rules are written only once, in the HTML.

VIII. Your turn: validate the forms of your project

  1. List the forms: as a team, list every form of your project (sign up, login, contact, and the create/update forms of each CRUD web service) and, for each field, write its rules (required? type? length? format? range?).
  2. HTML5 first: give every input the correct type, a <label>, a name, and the attributes required, minlength/maxlength, min/max and pattern that match your rules. Test the forms without JavaScript.
  3. Structure: wrap each field in a .Form_Control with a <small class="Error_Message">, add novalidate to the form, and add the .error / .success styles to your CSS (keep them responsive, see Lab 3).
  4. Shared helpers: create one file (for example assets/JS/validation.js) with setErrorFor, setSuccessFor, your regular expressions (isEmail, isPhoneNumber, ...) and validateField, so that every team member reuses the same code.
  5. Validators: for each form, write the validators object with one function and a clear English (or Arabic/French, but consistent) message per field. Include your business rules (dates, ranges, two fields that must match, ...).
  6. Passwords: on the sign-up form, add the strength meter and the confirmation check.
  7. Real time: attach the blur, input and submit listeners as in section VII.
  8. Test: for every field, try an empty value, a value that is too short/too long, a wrong format, and a correct value. Try a phone number starting with 08, an email without a domain, a birthdate in the future, and two different passwords.
  9. Bypass test: in the DevTools, remove required from an input or disable JavaScript, and submit the form. Write down what your server receives: this is what your PHP validation will have to handle.
Tip: Start from the demo form: rewrite Form_Validation.js with const, one message per field and the submit event, then adapt it to your own forms.
