Lab 2: Project structure

Instructions

In this lab you will set up your project folder and then rebuild, step by step, the HTML and CSS of the demo travel website Syaha (سياحة). Every step adds one component (navigation bar, hero, destinations, trips, features, footer) with its own stylesheet.
We build the desktop version only: making it work on phones and tablets is the subject of Lab 3, and the JavaScript (menu, slider) comes in Lab 4. Then apply the same method to the pages of your own team project.

I. Get your project

At this point you should have a team and a project (see Lab 0). Your teacher created a GitHub repository for it. Since we use XAMPP, clone it inside the htdocs folder:
  • Windows: C:/xampp/htdocs
  • Mac: /Applications/XAMPP/xamppfiles/htdocs
  • Linux: /opt/lampp/htdocs
You find the URL of your repository in the ENSIA-AI organization on GitHub (it has the name of your project). 
$ cd C:/xampp/htdocs
$ git clone https://github.com/the-repository-url
Tip: With GitHub Desktop: File > Clone repository, paste the URL, choose C:/xampp/htdocs as local path and click Clone.

Start Apache from the XAMPP control panel and open http://localhost/your-project-name in the browser. Any file you create in the folder is now served at http://localhost/your-project-name/file-name.

III. Project structure

Unless you use a framework that imposes its own structure, organize your files so that anybody in the team finds things immediately. Pages stay at the root, and everything they use goes into assets, one folder per type of file: 

syaha/                      <- the repository you cloned into xampp/htdocs
├── index.html              home page        (demo: Lab_2_Page.html)
├── Services.html           all the services
├── About_Us.html           about us
├── Contact_Us.html         contact
├── Login.html              login forms
├── NotFound.html           page not found
└── assets/
    ├── css/
    │   ├── Lab_2_Page.css      reset shared by every page
    │   ├── Nav_Bar.css         navigation bar
    │   ├── Hero.css            hero banner
    │   ├── Slider.css          image slider of the hero
    │   ├── Destination.css     "destinations" section
    │   ├── Trip.css            "trips" cards
    │   ├── Features.css        "why choose us" section
    │   ├── Lab_2_Footer.css    footer
    │   ├── Services.css        service cards
    │   ├── About_Us.css        about us text and team
    │   ├── Contact_Us.css      contact details, form and map
    │   ├── NotFound.css        404 page
    │   └── Logins.css          login page
    ├── images/                 photos (copy them from SRC/IMAGES and SRC/IMAGES/Lab_2)
    ├── js/                     empty for now (Lab 4)
    └── fonts/                  local fonts, if any
Two rules make team work much easier:
  1. One component, one stylesheet. The navigation bar is styled only in Nav_Bar.css, the footer only in Lab_2_Footer.css, and so on. Each member can own some components and work on them without conflicts in Git.
  2. Pages reuse components. Every page links only the stylesheets of the components it contains: the About page does not need Trip.css.
Tip: pick one naming convention and keep it everywhere. The demo uses Capitalized_Words for files and classes. Remember that the file Hero.css and the link hero.css are different on a Linux server.

The first stylesheet, Lab_2_Page.css, removes the default margins and paddings that browsers add to elements, and switches every element to box-sizing: border-box so that width includes padding and border. It also enables smooth scrolling for links such as #Destinations, and scroll-margin-top stops the fixed navigation bar from hiding the top of the section you jump to. 

* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
  font-family: "Cairo", "Poppins", sans-serif;
  gap: 0;
}

html {
  scroll-behavior: smooth;
}

/* leave room for the fixed navigation bar when jumping to #Destinations, #Trips... */
section {
  scroll-margin-top: 120px;
}
Fonts: Cairo has Arabic and Latin letters. The two preconnect links let the browser open the connection to Google Fonts early. See External fonts in CSS fundamentals to choose another font.
Arabic text: the demo sets direction: rtl on titles, paragraphs and grids, and uses row-reverse in flex containers to put things on the right. An alternative is to write <html lang="ar" dir="rtl"> once: the whole page then flows from right to left. If your project is in English or French you will not need any of this.

What to notice:

Hero.css makes the hero as high as the screen (100vh) and as wide as the page (100%), and places the text over the photos:

  text-decoration: none;

  border-radius: 6px;
  font-size: 1.5rem;

}
Careful: 100vw looks like "the width of the page", but it includes the vertical scrollbar (about 15px on Windows). A box of width: 100vw is therefore wider than the page and adds a horizontal scrollbar. Use width: 100% for full-width boxes.
  • Overlay technique: the hero is position: relative, and the text is position: absolute. top: 50%; left: 50%; transform: translate(-50%, -50%) centers the text both ways.
  • The button (.Show) uses a linear-gradient as background image, and on :hover reverses the gradient and grows with transform: scale(1.1).
  • Scope your selectors: .Hero img only targets the images inside the hero. A bare img { ... } rule would make every image of the site full-screen, and each other component would have to undo it.
  • .Hero_Small is a shorter (70vh) variant. The demo pages do not use it: to use it, also make the image inside 70vh high, otherwise the 100vh image overflows the box.

XII. Step 9: reusable components with PHP

Copying the same navigation bar and footer into six pages has a cost: one change must be repeated six times. As soon as you use PHP (we are already on XAMPP), you can write each shared component once and include it. Rename your pages .php and create a components folder: 

syaha/
├── index.php
├── Services.php
├── ...
├── components/
│   ├── header.php      <head> + navigation bar
│   └── footer.php      footer + </body></html>
└── assets/

components/footer.php contains the footer of Step 7, and components/header.php the beginning of the page up to the navigation bar of Step 2. Each page then contains only what is specific to it: 

<?php include 'components/header.php'; ?>
    <main>
        <!-- hero, destinations, trips and features of the home page -->
    </main>
<?php include 'components/footer.php'; ?>

Open http://localhost/your-project-name/index.php: the browser receives the same HTML as before, assembled by the server. Each member can work on their components and pages independently, and an update of a component is visible on every page at once.

Tip: the stylesheets and the Active link differ from page to page. Set variables such as $styles = ['Trip.css']; and $page = 'services'; before the include, and use them in the header. PHP itself is covered from Introduction to PHP.

XIII. Your turn

Apply the same method to your team project:
  1. Draw the site map and list the pages of your project (see the template in Resources).
  2. For each page, list its components. Components used on several pages (header, footer, cards...) are written once.
  3. Create the folder structure of Section III and commit it.
  4. Share the components between the team members; each member creates the HTML and the stylesheet of their components, in a branch.
  5. Assemble the pages, check them in the browser at http://localhost/..., and validate the HTML with the W3C validator.
  6. Commit and push regularly with meaningful messages.

Deliverables

  • The repository follows a clear structure: pages at the root, assets/css, assets/js, assets/images (and components/ if you use PHP includes).
  • All the pages of your project exist with their final HTML structure and desktop styling.
  • One stylesheet per component, linked only by the pages that use it.
  • Shared components (header, footer) are identical on every page, or included with PHP.
  • Images have meaningful alt texts and form fields have labels.
  • Every member has commits for the components they built.
  • Responsiveness is added in Lab 3; together they form the "HTML/CSS" milestone of the Deadlines table.
