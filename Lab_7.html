I. element.style vs classList

There are two ways to change the style of an element from JavaScript:
1. Write inline styles with the style property. This is the same as writing a style="..." attribute in the HTML, so it overrides the rules of your CSS files.
2. Add or remove CSS classes with the classList property. The styles stay in your CSS file and JavaScript only decides which classes an element has.
The style property uses camelCase names (backgroundColor for background-color) and its values are always strings with units.

The style property

const card = document.querySelector(".Product_Card");

// Write inline styles: camelCase names, string values WITH units
card.style.backgroundColor = "#8c1515";
card.style.marginTop = "20px";
card.style.borderRadius = "10px";

// setProperty / removeProperty accept the real CSS (hyphenated) names
card.style.setProperty("border-left", "6px solid gold");
card.style.removeProperty("margin-top");

// Reading only returns what was set INLINE, not what comes from your .css files
console.log(card.style.color); // "" if the color is defined in Styles.css

// Replace all inline styles at once
card.style.cssText = "color: white; padding: 1em;";
Common mistake: card.style.width = 200; does nothing because the unit is missing. Write card.style.width = "200px"; or card.style.width = size + "px";.

The classList property

classList is a list of the classes of an element with methods to modify it without touching the other classes. This is the preferred way to show, hide, highlight or animate elements. 

.Product_Card.Selected {
  box-shadow: 0 0 0 3px #8c1515;
}

.Hidden {
  display: none;
}
        
const card = document.querySelector(".Product_Card");

card.classList.add("Selected");            // add a class (or several: add("A", "B"))
card.classList.remove("Selected");         // remove a class
card.classList.toggle("Selected");         // add if missing, remove if present; returns true or false
card.classList.toggle("Hidden", stock === 0); // "force": add when true, remove when false
card.classList.replace("Small", "Large");  // swap one class for another

if (card.classList.contains("Selected")) {
  console.log("This card is selected");
}

// className is the whole class attribute as one string: assigning it REPLACES all classes
card.className = "Product_Card Selected";
Use When
classList Show/hide, open/close, active/inactive, error/valid, themes: any state you can describe in advance in CSS.
style Values computed at run time that cannot be written in advance: a position, a width in pixels, a translation that depends on a counter.
Tip: keep your design in CSS and your logic in JavaScript. If you find yourself writing element.style.display = "none", create a .Hidden class instead. Your team members can then change the look without reading your JavaScript.

II. CSS custom properties and getComputedStyle

CSS custom properties (also called CSS variables) are declared with two dashes and used with var(). When JavaScript changes a variable, every rule that uses it updates at once.
Custom properties can only be set with style.setProperty() (not with camelCase), and read with getPropertyValue(). 

:root {
  --accent: #8c1515;
  --radius: 8px;
}

.Btn {
  background-color: var(--accent);
  border-radius: var(--radius);
}
        
const root = document.documentElement; // the <html> element, where :root variables live

root.style.setProperty("--accent", "#027b92"); // every element using var(--accent) changes
root.style.setProperty("--radius", "20px");

// Read the current value (note the leading space that CSS may keep: use trim())
const accent = getComputedStyle(root).getPropertyValue("--accent").trim();

root.style.removeProperty("--accent"); // back to the value written in the CSS file

// A variable can also be overridden for one element and its children only
document.querySelector(".Promo").style.setProperty("--accent", "green");

getComputedStyle()

element.style only knows inline styles. To know the final value the browser actually uses (after applying all your CSS files, inheritance and media queries), call getComputedStyle(element). The returned object is read-only and values are resolved: lengths are in px and colors in rgb(). 

const title = document.querySelector(".Title");
const computed = getComputedStyle(title);

console.log(computed.fontSize);  // e.g. "32px" even if the CSS says 2em
console.log(computed.color);     // e.g. "rgb(140, 21, 21)"
console.log(computed.display);   // "block"

// To compute with it, convert to a number, then WRITE with element.style
const size = parseFloat(computed.fontSize);
title.style.fontSize = size * 1.2 + "px";

III. Transitions triggered by class changes

A CSS transition animates a property every time its value changes. Combined with classList, this gives smooth animations with almost no JavaScript: CSS describes the two states and the animation, JavaScript only switches the class.
Important: display cannot be animated. To fade or slide an element in and out, animate opacity, transform, max-height or visibility instead. 

.Panel {
  max-height: 0;
  opacity: 0;
  overflow: hidden;
  transition: max-height 0.3s ease, opacity 0.3s ease;
}

.Panel.Open {
  max-height: 500px; /* larger than the real content */
  opacity: 1;
}

/* Respect users who asked their system to reduce animations */
@media (prefers-reduced-motion: reduce) {
  .Panel {
    transition: none;
  }
}
        
const panel = document.querySelector(".Panel");

document.querySelector(".Panel_Btn").addEventListener("click", () => {
  panel.classList.toggle("Open");
});

// Optional: run code when the animation is finished
panel.addEventListener("transitionend", (event) => {
  if (event.propertyName === "opacity") {
    console.log("Panel is now", panel.classList.contains("Open") ? "open" : "closed");
  }
});
Tip: if you create an element and add its "visible" class in the same instant, the browser never sees the first state and there is no transition. Add the class one frame later with requestAnimationFrame(() => el.classList.add("Open"));.

IV. Hamburger and drop-down menus

How this website does it

The navigation bar of this course website is built by SRC/JS/Script.js. On small screens, the menu icon switches the menu between two classes and changes the Font Awesome icon: 

// Excerpt of SRC/JS/Script.js
function handle_click() {
  clicked = !clicked;
  if (!clicked) {
    document.getElementById("Nav_Bar_Menu_ID").className = "Nav_Bar_Menu";
    document.getElementById("Menu_Icon_I_ID").className = "fas fa-bars";
  } else {
    document.getElementById("Nav_Bar_Menu_ID").className = "Nav_Bar_Menu_Active";
    document.getElementById("Menu_Icon_I_ID").className = "fas fa-times";
  }
}

This works, but it keeps the state in a separate clicked variable and uses className, which erases any other class of the element. A cleaner version lets classList.toggle() hold the state (its return value tells you if the menu is now open) and updates aria-expanded so screen readers know the menu state.

The drop-down menu

Here is the drop-down code given in previous labs (SRC/Labs/Lab_4+/Drop_Down_Menu.js): 

var clicked = false,
  Menu_Icon_ID = document.getElementById("Menu_Icon_ID"),
  Nav_Bar_Menu_ID = document.getElementById("Nav_Bar_Menu_ID"),
  Burger_Icon_ID = document.getElementById("Burger_Icon_ID");

function Change_State() {
  this.clicked = !clicked;
}

Menu_Icon_ID.addEventListener("click", () => {
  Change_State();
  if (!clicked) {
    Nav_Bar_Menu_ID.classList.remove("active");
    Burger_Icon_ID.className = "fas fa-bars";
  } else {
    Nav_Bar_Menu_ID.classList.toggle("active");
    Burger_Icon_ID.className = "fas fa-times";
  }
});

The idea is right (a class active opens the menu) but there is a trap: this.clicked = !clicked only works because, in a classic non-strict script, this inside a plain function is window and a top-level var becomes a property of window. In a module (type="module") or in strict mode, this is undefined and the code crashes. Write clicked = !clicked;, or better, drop the variable and ask the element with classList.contains().
The version below supports several sub-menus, closes the others when one opens, and closes everything on an outside click or the Escape key. 

.Has_Sub {
  position: relative;
}

.Sub_Menu {
  position: absolute;
  top: 100%;
  left: 0;
  min-width: 180px;
  list-style: none;
  opacity: 0;
  visibility: hidden;
  transform: translateY(-8px);
  transition: opacity 0.2s ease, transform 0.2s ease, visibility 0.2s;
}

.Has_Sub.Open > .Sub_Menu {
  opacity: 1;
  visibility: visible;
  transform: translateY(0);
}
        
function closeAllSubMenus() {
  document.querySelectorAll(".Has_Sub.Open").forEach((item) => {
    item.classList.remove("Open");
    item.querySelector(".Sub_Toggle").setAttribute("aria-expanded", "false");
  });
}

document.querySelectorAll(".Has_Sub").forEach((item) => {
  const toggle = item.querySelector(".Sub_Toggle");
  toggle.addEventListener("click", (event) => {
    event.stopPropagation(); // do not let the document listener below close it again
    const wasOpen = item.classList.contains("Open");
    closeAllSubMenus();
    if (!wasOpen) {
      item.classList.add("Open");
      toggle.setAttribute("aria-expanded", "true");
    }
  });
});

document.addEventListener("click", closeAllSubMenus);
document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") closeAllSubMenus();
});
Tip: a pure CSS drop-down with .Has_Sub:hover > .Sub_Menu works with a mouse but not on touch screens and not with the keyboard. Keep the hover rule if you like it, but always add the click version (you can also add :focus-within).

V. Image slider (carousel)

The first version of the slider used in previous labs (SRC/Labs/Lab_4+/Image_Slider.js, since fixed) places each slide next to the previous one and moves all of them with transform: translateX(): 

var Counter = 1,
  Slides = document.querySelectorAll(".Slide");

Slides.forEach((Slide, index) => {
  Slide.style.left = index * 100 + "%";   // slide 0 at 0%, slide 1 at 100%, ...
});

const Slide_Images = () => {
  Slides.forEach((Slide) => {
    Slide.style.transform = "translateX(-" + (Counter % Slides.length) * 100 + "%)";
  });
};

function Slide_Previous(event) { Counter--; Slide_Images(); }
function Slide_Next(event) { Counter++; Slide_Images(); }

Note that here style is the right tool: the translation is computed from a counter and cannot be written in advance in CSS. However, the code has two bugs worth understanding:
1. Counter starts at 1 while the first slide shown is slide 0, so the first click on "next" jumps directly to slide 2.
2. Clicking "previous" on the first slide makes Counter negative. In JavaScript -1 % 3 is -1, so the code produces translateX(--100%), which is invalid CSS. The fix is (index + length) % length.
The improved version below moves one "track" instead of every slide, adds navigation dots (whose active state is a class), auto-plays, and pauses when the mouse is over the slider.

    <img class="Slide" src="assets/Images/slide_2.jpg" alt="Describe slide 2" />
    <img class="Slide" src="assets/Images/slide_3.jpg" alt="Describe slide 3" />
  </div>
  <button type="button" class="Slider_Btn Prev" aria-label="Previous slide">
    <i class="fa-solid fa-chevron-left"></i>
  </button>
  <button type="button" class="Slider_Btn Next" aria-label="Next slide">

</div>

function createSlider(slider, delay = 4000) {
  const track = slider.querySelector(".Slides_Track");
  const slides = slider.querySelectorAll(".Slide");
  const dotsBox = slider.querySelector(".Slider_Dots");
  let current = 0;
  let timer = null;

  // One dot per slide
  const dots = Array.from(slides, (slide, index) => {
    const dot = document.createElement("button");
    dot.type = "button";
    dot.className = "Dot";
    dot.setAttribute("aria-label", `Go to slide ${index + 1}`);
    dot.addEventListener("click", () => {
      goTo(index);
      restart();
    });
    dotsBox.appendChild(dot);
    return dot;
  });

  function goTo(index) {
    current = (index + slides.length) % slides.length; // never negative
    track.style.transform = `translateX(-${current * 100}%)`;
    dots.forEach((dot, i) => dot.classList.toggle("Active", i === current));
  }

  function start() {
    timer = setInterval(() => goTo(current + 1), delay);
  }
  function stop() {
    clearInterval(timer);
  }
  function restart() {
    stop();
    start();
  }

  slider.querySelector(".Prev").addEventListener("click", () => {
    goTo(current - 1);
    restart();
  });
  slider.querySelector(".Next").addEventListener("click", () => {
    goTo(current + 1);
    restart();
  });
  slider.addEventListener("mouseenter", stop);
  slider.addEventListener("mouseleave", start);

  goTo(0);
  start();
}

// Works for every slider of the page
document.querySelectorAll(".Slider").forEach((slider) => createSlider(slider));

VI. Modal dialog

SRC/JS/Script.js opens its dialog with Dialog.style.display = "block" and closes it with "none". Today, HTML has a native <dialog> element: showModal() opens it on top of the page with a dark backdrop, blocks the rest of the page, moves the keyboard focus inside, and closes it with the Escape key, all for free. A <form method="dialog"> inside the dialog closes it and puts the value of the clicked button in dialog.returnValue. 

<button type="button" class="Btn" id="Open_Delete_Dialog">Delete my account</button>

<dialog class="Modal" id="Delete_Dialog" aria-labelledby="Delete_Dialog_Title">
  <div class="Modal_Content">
    <h2 id="Delete_Dialog_Title">Are you sure?</h2>
    <p>This action cannot be undone.</p>
    <form method="dialog">
      <button value="cancel">Cancel</button>
      <button value="confirm">Yes, delete</button>
    </form>
  </div>
</dialog>
        
.Modal {
  border: none;
  border-radius: 10px;
  padding: 0; /* padding goes on .Modal_Content so backdrop clicks are easy to detect */
  max-width: 90vw;
}

.Modal_Content {
  padding: 1.5em;
}

.Modal::backdrop {
  background-color: rgba(0, 0, 0, 0.6);
}

.Modal[open] {
  animation: Pop_In 0.2s ease-out;
}

@keyframes Pop_In {
  from { opacity: 0; transform: scale(0.9); }
  to   { opacity: 1; transform: scale(1); }
}
        
const deleteDialog = document.getElementById("Delete_Dialog");

document.getElementById("Open_Delete_Dialog").addEventListener("click", () => {
  deleteDialog.showModal();
});

// A click on the dark backdrop has the dialog itself as target
deleteDialog.addEventListener("click", (event) => {
  if (event.target === deleteDialog) deleteDialog.close("cancel");
});

deleteDialog.addEventListener("close", () => {
  if (deleteDialog.returnValue === "confirm") {
    console.log("Confirmed: submit the real delete form here (or call your PHP service, Lab 11)");
  }
});
Tip: if you prefer to keep a <div> modal like the one of Script.js, at least use classList.add("Open") instead of style.display, and handle the Escape key and the focus yourself. The live demo in section II uses a native <dialog>.

VII. Dark/light theme remembered with localStorage

A theme toggle combines everything from this lab: colors are CSS custom properties, the theme is a data-theme attribute on <html>, and JavaScript switches the attribute.
localStorage stores strings in the browser, per website, and keeps them after the browser is closed (sessionStorage forgets them when the tab is closed). We use it to remember the choice of the user. When nothing is saved, we follow the system preference (prefers-color-scheme). 

:root {
  --bg: #ffffff;
  --text: #3f3c30;
  --card-bg: #f5f5f5;
  --accent: #8c1515;
}

:root[data-theme="dark"] {
  --bg: #121212;
  --text: #e8e6e3;
  --card-bg: #1e1e1e;
  --accent: #ff6b6b;
}

body {
  background-color: var(--bg);
  color: var(--text);
  transition: background-color 0.3s ease, color 0.3s ease;
}

.Card {
  background-color: var(--card-bg);
}

To avoid a "flash" of the light theme when a dark-theme user loads a page, apply the saved theme with a tiny script in the <head>, before the page is drawn: 

<head>
  ...
  <script>
    (function () {
      let theme = null;
      try {
        theme = localStorage.getItem("theme");
      } catch (error) {
        // storage may be blocked (private mode): fall back to the system preference
      }
      if (theme !== "dark" && theme !== "light") {
        theme = window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
      }
      document.documentElement.dataset.theme = theme;
    })();
  </script>
</head>

Then the toggle button (for example in your header component) and its script: 

<button type="button" class="Theme_Toggle" id="Theme_Toggle" aria-label="Toggle dark theme" aria-pressed="false">
  <i class="fa-solid fa-moon"></i>
</button>
        
const themeBtn = document.getElementById("Theme_Toggle");
const themeIcon = themeBtn.querySelector("i");

function applyTheme(theme) {
  const isDark = theme === "dark";
  document.documentElement.dataset.theme = theme;
  themeIcon.classList.toggle("fa-moon", !isDark);
  themeIcon.classList.toggle("fa-sun", isDark);
  themeBtn.setAttribute("aria-pressed", isDark);
}

// Sync the icon with the theme chosen by the <head> script
applyTheme(document.documentElement.dataset.theme || "light");

themeBtn.addEventListener("click", () => {
  const next = document.documentElement.dataset.theme === "dark" ? "light" : "dark";
  applyTheme(next);
  try {
    localStorage.setItem("theme", next);
  } catch (error) {
    // not saved, but the theme still changes for this page
  }
});
Remember: localStorage only stores strings. To store an object use localStorage.setItem("cart", JSON.stringify(cart)) and JSON.parse(localStorage.getItem("cart")). Never store passwords or anything secret in it. If your PHP code needs to know the theme, use a cookie instead (see Sessions and Cookies).

VIII. Your turn

Add the interactive behaviours to your team project. Split the steps between team members.

  1. Create a file assets/JS/ui.js and include it on every page, for example at the end of your footer component: <script src="assets/JS/ui.js" defer></script>. Each component must check that its elements exist before adding listeners (e.g. if (slider) {...}) because not every page has a slider.
  2. Hamburger menu: add the burger button to your header component, write the CSS media query and the toggle. Test it with the device toolbar of the browser DevTools (Ctrl+Shift+M).
  3. Drop-down menu: add at least one sub-menu (categories, account, ...) that opens on click and closes on outside click and Escape.
  4. Image slider: add a slider with at least 3 of your own images (with meaningful alt text) to your home page or to a product/details page.
  5. Modal dialog: use a <dialog> to confirm a delete action of one of your CRUD services, or to show a login/details form.
  6. Theme toggle: move the colors of your main CSS file into custom properties, add a dark theme, the toggle button and the <head> script. Reload the page and check that the choice is remembered (DevTools > Application > Local Storage).
  7. Clean up: search your JavaScript for .style.display and similar show/hide code and replace it with classes.
  8. Test: no errors in the console, every component works with the keyboard (Tab, Enter, Escape) and at phone width.
  9. Commit and push: git commit -m "Lab 7: menus, slider, modal and theme" then git push.
