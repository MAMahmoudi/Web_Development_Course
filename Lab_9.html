Lab 11: AJAX and JSON APIs

Instructions

Until now, every action of your website (add, search, delete...) submits a form and reloads the whole page. In this lab you will make your pages talk to PHP without reloading.
You will write PHP endpoints that return JSON, call them from JavaScript with fetch() and async/await, send data as FormData and as JSON, handle errors, show loading indicators, and build a live search and a delete-without-reload.
This work counts toward the "PHP/AJAX" milestone of the Deadlines table. Review the lectures Introduction to AJAX and jQuery (jQuery AJAX part), and make sure your PDO connection from Lab 6 works.

I. The big picture

AJAX (Asynchronous JavaScript And XML) means: JavaScript sends an HTTP request in the background, the server answers with data (today almost always JSON, not XML), and JavaScript updates only the part of the page that changed. The flow of one request is:
1. The user types, clicks or submits a form.
2. JavaScript calls fetch("api/products.php"). The page stays on screen.
3. Apache runs the PHP file, which queries MySQL with PDO.
4. PHP answers with a status code (200, 404, 500...) and a JSON body, never with HTML.
5. JavaScript reads the JSON and updates the DOM (Lab 7 techniques).

In this lab we use a products service as an example. Replace it with the services of your own project. A suggested structure: 

your_project/
├── config/
│   └── db.php            (PDO connection, Lab 6)
├── api/
│   └── products.php      (JSON endpoint: list/search, create, delete)
├── assets/JS/
│   ├── api.js            (a reusable fetch helper)
│   └── products.js       (the logic of the products page)
└── products.php          (the page the user sees)

II. A PHP endpoint that returns JSON

An endpoint is a PHP file that is called by JavaScript, not displayed to the user. It must:
1. Say that it returns JSON: header('Content-Type: application/json'), before any output.
2. Set the HTTP status code with http_response_code(): JavaScript uses it to know whether the request succeeded.
3. Convert PHP arrays to JSON with json_encode(): an associative array becomes a JSON object, a list becomes a JSON array.
4. Output nothing else: no HTML, no echo "debug", no PHP warnings. A single extra character makes the JSON invalid.

The connection (from Lab 6)

<?php
// config/db.php
$host = 'localhost';

$pdo = new PDO($dsn, $user, $pass, $options);

The endpoint: GET (list and search)

<?php
// api/products.php
header('Content-Type: application/json; charset=utf-8');

function send_json($data, int $status = 200): void
{
    http_response_code($status);
    echo json_encode($data, JSON_UNESCAPED_UNICODE);
    exit; // stop here: nothing else may be printed
}

try {
    require __DIR__ . '/../config/db.php';
    $method = $_SERVER['REQUEST_METHOD'];

    if ($method === 'GET') {
        $q = trim($_GET['q'] ?? '');
        if ($q === '') {
            $stmt = $pdo->query('SELECT id, name, price, stock FROM products ORDER BY id DESC');
        } else {
            // NEVER put $q directly in the SQL string: use a placeholder
            $stmt = $pdo->prepare(
                'SELECT id, name, price, stock FROM products WHERE name LIKE ? ORDER BY name LIMIT 20'
            );
            $stmt->execute(['%' . $q . '%']);
        }
        send_json($stmt->fetchAll());
    }

    if ($method === 'POST') {
        // section IV
    }

    if ($method === 'DELETE') {
        // section VI
    }

    send_json(['error' => 'Method not allowed'], 405);
} catch (PDOException $e) {
    error_log($e->getMessage());              // details go to the Apache error log...
    send_json(['error' => 'Database error'], 500); // ...not to the user

III. fetch() GET with async/await, errors and loading

fetch(url, options) returns a Promise of a Response. With await we wait for it without blocking the page (only inside an async function or a module). Two things are essential:
1. fetch() only rejects on network problems (server unreachable, request cancelled). A 404 or 500 response is not an exception: you must check response.ok (true for status 200-299).
2. response.json() is also asynchronous and must be awaited.
Instead of repeating these checks in every call, write one helper and reuse it everywhere: 

// assets/JS/api.js
export async function apiFetch(url, options = {}) {
  let response;
  try {
    response = await fetch(url, options);
  } catch (error) {
    if (error.name === "AbortError") throw error; // cancelled on purpose (section V)
    throw new Error("Cannot reach the server. Is Apache running?");
  }

  // Our PHP always answers JSON, even for errors
  let data = null;
  const type = response.headers.get("Content-Type") || "";
  if (type.includes("application/json")) {
    data = await response.json(); // throws a SyntaxError if PHP printed a warning
  }

  if (!response.ok) {
    const error = new Error(data?.error || `HTTP error ${response.status}`);
    error.status = response.status;
    error.details = data;
    throw error;
  }
  return data;
}

Loading and displaying the data

// assets/JS/products.js
import { apiFetch } from "./api.js";

const API = "api/products.php";
const tbody = document.getElementById("Products_Body");
const statusBox = document.getElementById("Products_Status");

function setStatus(message, type = "info") {
  statusBox.textContent = message;
  statusBox.className = `Status ${type}`;
}

function renderProducts(products) {
  tbody.replaceChildren(); // empty the table body
  if (products.length === 0) {
    const cell = tbody.insertRow().insertCell();
    cell.colSpan = 4;
    cell.textContent = "No products found.";
    return;
  }
  for (const product of products) {
    const row = tbody.insertRow();
    row.dataset.id = product.id; // <tr data-id="3">
    row.insertCell().textContent = product.name; // textContent, never innerHTML, for data
    row.insertCell().textContent = Number(product.price).toFixed(2);
    row.insertCell().textContent = product.stock;
    const deleteBtn = document.createElement("button");
    deleteBtn.type = "button";
    deleteBtn.className = "Delete_Btn";
    deleteBtn.textContent = "Delete";
    row.insertCell().appendChild(deleteBtn);
  }
}

async function loadProducts(query = "", signal) {
  setStatus("Loading...", "loading");
  tbody.setAttribute("aria-busy", "true");
  try {
    const url = query ? `${API}?q=${encodeURIComponent(query)}` : API;
    const products = await apiFetch(url, { signal });
    renderProducts(products);
    setStatus(`${products.length} product(s)`);
  } catch (error) {
    if (error.name === "AbortError") return; // a newer search replaced this one
    setStatus(error.message, "error");
  } finally {
    tbody.removeAttribute("aria-busy");
  }
}

loadProducts();
Security: the product names come from users. Putting them in innerHTML would let someone save <img src=x onerror=alert(1)> as a name and run JavaScript in other users' browsers (XSS). textContent always displays text. See Lab 12 and the Security lecture.

For comparison, the same request written with .then() instead of await:

fetch("api/products.php")
  .then((response) => {
    if (!response.ok) throw new Error(`HTTP error ${response.status}`);
    return response.json();
  })
  .then((products) => renderProducts(products))
  .catch((error) => setStatus(error.message, "error"));

IV. Sending data with POST: FormData and JSON

There are two common ways to send data to PHP:
1. FormData: new FormData(form) collects all the fields of a form (using their name attributes), including files. PHP reads it with $_POST (and $_FILES) exactly like a normal form. Do not set the Content-Type header yourself: the browser does it.
2. JSON body: JSON.stringify(object) with the header Content-Type: application/json. PHP does not fill $_POST in this case: it must read the raw body with file_get_contents('php://input') and decode it with json_decode(..., true) (the true gives an associative array).

PHP: the POST branch

if ($method === 'POST') {
    // Accept both a JSON body and a classic form body
    $contentType = $_SERVER['CONTENT_TYPE'] ?? '';
    if (str_contains($contentType, 'application/json')) {
        $input = json_decode(file_get_contents('php://input'), true);
        if (!is_array($input)) {
            send_json(['error' => 'Invalid JSON'], 400);
        }
    } else {
        $input = $_POST; // FormData or normal form
    }

    // Always validate on the server, even if JavaScript already did (Lab 4)
    $name  = trim($input['name'] ?? '');
    $price = filter_var($input['price'] ?? null, FILTER_VALIDATE_FLOAT);
    $stock = filter_var($input['stock'] ?? null, FILTER_VALIDATE_INT);

    $errors = [];
    if ($name === '' || mb_strlen($name) > 100) {
        $errors['name'] = 'Name is required (100 characters max).';
    }
    if ($price === false || $price < 0) {
        $errors['price'] = 'Price must be a positive number.';
    }
    if ($stock === false || $stock < 0) {
        $errors['stock'] = 'Stock must be a positive integer.';
    }
    if ($errors) {
        send_json(['error' => 'Validation failed', 'errors' => $errors], 422);
    }

    $stmt = $pdo->prepare('INSERT INTO products (name, price, stock) VALUES (:name, :price, :stock)');
    $stmt->execute([':name' => $name, ':price' => $price, ':stock' => $stock]);

    send_json([
        'id'    => (int) $pdo->lastInsertId(),
        'name'  => $name,
        'price' => $price,
        'stock' => $stock,
    ], 201);
}

// assets/JS/products.js (continued)
const form = document.getElementById("Add_Product_Form");
const formErrors = document.getElementById("Form_Errors");

form.addEventListener("submit", async (event) => {
  event.preventDefault(); // stop the normal submit and page reload
  const submitBtn = form.querySelector("button[type=submit]");
  submitBtn.disabled = true; // avoid double submissions
  submitBtn.textContent = "Saving...";
  formErrors.textContent = "";

  try {
    const created = await apiFetch(API, {
      method: "POST",
      body: new FormData(form), // no Content-Type header here!
    });
    form.reset();
    setStatus(`"${created.name}" added.`, "success");
    loadProducts();
  } catch (error) {
    if (error.status === 422 && error.details?.errors) {
      formErrors.textContent = Object.values(error.details.errors).join(" ");
    } else {
      formErrors.textContent = error.message;
    }
  } finally {
    submitBtn.disabled = false;
    submitBtn.textContent = "Add";
  }
});

JavaScript: sending a JSON body

Use JSON when the data does not come from a form, for example an object built by your code:

const newProduct = { name: "Webcam", price: 4500, stock: 8 };

const created = await apiFetch(API, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(newProduct),
});
console.log("New id:", created.id);
FormData JSON body
Build it with new FormData(form) JSON.stringify(object)
Content-Type Set automatically by the browser application/json (set it yourself)
Read in PHP with $_POST, $_FILES json_decode(file_get_contents('php://input'), true)
Best for Existing forms, file uploads Data built in JavaScript, nested data, DELETE/PUT requests
Common mistake: sending JSON and reading $_POST in PHP. The array is empty and every field looks "missing". Look at the request in DevTools > Network > Payload to check what was really sent.

V. A live search box with debounce

A live search updates the results while the user types. Listening to the input event and calling the server for every key would send 5 requests for the word "mouse". Debouncing waits until the user stops typing for a short delay (here 300 ms) and then sends a single request: each new key press cancels the previous timer.
Requests can also come back in the wrong order (the answer for "mo" arriving after the answer for "mouse"). An AbortController cancels the previous request when a new one starts. 

// assets/JS/products.js (continued)
function debounce(fn, delay = 300) {
  let timerId;
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const searchInput = document.getElementById("Search_Input");
let searchController = null;

const runSearch = debounce((query) => {
  searchController?.abort(); // cancel the previous, now useless, request
  searchController = new AbortController();
  loadProducts(query, searchController.signal);
}, 300);

searchInput.addEventListener("input", () => {
  runSearch(searchInput.value.trim());
});

The PHP side is the GET branch of section II: the search term is sent as ?q=... (encoded with encodeURIComponent) and used in a prepared statement with LIKE ?. The LIMIT 20 keeps the answer small and fast.

Tip: open DevTools > Network, type quickly in the search box and watch: only one request should be sent after you stop typing, and older requests are shown as "canceled".

VI. Deleting a row without reloading

The rows are created by JavaScript and replaced after every search, so adding a listener to each button would be lost. Instead we use event delegation: one listener on the <tbody>, and event.target.closest(".Delete_Btn") to find which button was clicked. The id of the product is stored in the data-id attribute of the row.
We send the request with the HTTP method DELETE and a JSON body. The row is removed from the DOM only after the server confirms. 

if ($method === 'DELETE') {
    // (In your project, check here that the user is logged in and allowed to delete,
    //  e.g. with $_SESSION, and answer 401/403 otherwise. See Lab 12.)
    $input = json_decode(file_get_contents('php://input'), true);
    $id = is_array($input) ? filter_var($input['id'] ?? null, FILTER_VALIDATE_INT) : false;
    if ($id === false) {
        send_json(['error' => 'A valid id is required'], 400);
    }

    $stmt = $pdo->prepare('DELETE FROM products WHERE id = ?');
    $stmt->execute([$id]);

    if ($stmt->rowCount() === 0) {
        send_json(['error' => 'Product not found'], 404);
    }
    send_json(['deleted' => $id]);
}
        
// assets/JS/products.js (continued)
tbody.addEventListener("click", async (event) => {
  const btn = event.target.closest(".Delete_Btn");
  if (!btn) return; // the click was not on a delete button

  const row = btn.closest("tr");
  const name = row.cells[0].textContent;
  if (!confirm(`Delete "${name}"?`)) return; // or use the <dialog> of Lab 7

  btn.disabled = true;
  row.classList.add("Removing"); // visual feedback while waiting
  try {
    await apiFetch(API, {
      method: "DELETE",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ id: Number(row.dataset.id) }),
    });
    row.remove();
    setStatus(`"${name}" deleted.`, "success");
  } catch (error) {
    row.classList.remove("Removing");
    btn.disabled = false;
    setStatus(error.message, "error");
  }
});
Note: a GET request must never modify data (browsers, link previews and search engines may call GET links on their own). Use POST or DELETE for any action that changes the database.

VII. fetch vs XMLHttpRequest vs jQuery $.ajax

The AJAX lecture and SRC/JS/AJAX.js use XMLHttpRequest, the original AJAX API, with an onreadystatechange callback. The jQuery lecture uses $.ajax(), $.get() and $.post(). Here is the same "load the products" request with both: 

// XMLHttpRequest (style of SRC/JS/AJAX.js)
const xhr = new XMLHttpRequest();
xhr.open("GET", "api/products.php");
xhr.responseType = "json";
xhr.onload = function () {
  if (xhr.status === 200) {
    renderProducts(xhr.response);
  } else {
    setStatus(`HTTP error ${xhr.status}`, "error");
  }
};
xhr.onerror = () => setStatus("Network error", "error");
xhr.send();
        
// jQuery
$.ajax({
  url: "api/products.php",
  method: "GET",
  dataType: "json",
})
  .done((products) => renderProducts(products))
  .fail((jqXHR) => setStatus(jqXHR.responseJSON?.error || "Request failed", "error"));

// $.post with a serialized form (PHP reads it with $_POST)
$.post("api/products.php", $("#Add_Product_Form").serialize()).done(() => loadProducts());
XMLHttpRequest fetch() jQuery $.ajax
Style Events and callbacks Promises, works with async/await Callbacks or .done()/.fail() (also awaitable)
Needs a library No No Yes, jQuery
HTTP errors (404, 500) Check xhr.status Not an exception: check response.ok Calls .fail()
Cancel a request xhr.abort() AbortController jqXHR.abort()
Upload progress Yes, xhr.upload.onprogress Not directly Yes, through the xhr option
Recommendation: use fetch() for new code in your project. If your team already uses jQuery on the pages (jQuery lecture), $.ajax is acceptable, but do not mix several styles for the same service. Whatever the client, the PHP endpoint stays exactly the same.
